第01回のファイルを読み込み、問い合わせを実行するための操作をまとめる。授業では教員が用意したSWI-Prologの環境から始める。手元で起動できない場合は授業内で教員と確認し、まず実演と本文の確認例を使って条件を読む。

ファイルと問い合わせの場所

プログラムはテキストエディタで .pl ファイルへ書き、問い合わせはSWI-Prologの入力欄へ書く。まずevent-basic.plを保存し、そのファイルのあるフォルダーで端末を開いて次を実行する。

swipl -q -s event-basic.pl

?- が出たらPrologの問い合わせを入力できる。たとえば available(aki,tue). と入力してEnterを押す。ここで swipl ... をもう一度入力するのではなく、読み込んだ事実や規則へ質問する。

?- available(aki, tue).
true.

?- available(chi, tue).
false.

プログラムの末尾にある /** <examples> ... */ は問い合わせの見本を並べたコメントであり、読み込んだだけでは実行されない。見本を一つずつ入力する。先頭の ?- は入力欄の目印なので、自分で重ねて入力しない。

次の答えと終了

can_work(P,tue). のような問い合わせには複数の答えがある。追加の答えを待つ状態になったら ; を押して次を求める。途中で答えを見るのを終えるときはEnterを押す。これらはSWI-Prologの標準の問い合わせ操作である。公式の操作説明

false は、最初から答えがない場合にも、追加の答えがもうない場合にも現れる。答えの末尾が . になって終わる場合もある。どの表示で終わるかより、それまでに得た答えを全部集めて本文の集合と比べよう。

処理が長く続いている場合はCtrl+Cで中断メニューを開き、a で問い合わせを中止する。入力できる ?- に戻ってから halt. を実行すると、Prologを終了して端末へ戻る。

編集と再実行

エディタでファイルを書き換えたら保存し、Prologで make. を実行して再読み込みする。その後、同じ問い合わせをもう一度入力する。画面に残っている古い答えは自動的には更新されない。

?- make.
?- can_work(P, D).

必修1など別のファイルへ移るときは、いったん halt. で終了し、swipl -q -s help-start.pl のように指定し直す。この教材の配布物にはそれぞれ全事実を入れてあるので、複数のファイルを同じPrologへ重ねて読み込む必要はない。

エラーの見分け方

答えがないことと、プログラムを正しく実行できなかったことを区別しよう。次の表で原因を一つずつ確かめてから、保存・再読み込み・再実行の順にやり直す。

表示や状況 確かめるところ
Syntax error 括弧、,、:-、末尾の . が正しいか
Unknown procedure 述語名と引数の数が合っているか。演習の規則をまだ書いていないか
Singleton variables の警告 変数の綴りが一か所だけ違わないか。同じ曜日のつもりで別名にしていないか
入力後も続きを待っている 問い合わせの末尾に . を書いたか
編集前と同じ答えになる 正しいファイルを保存し、make. で読み直したか
エラーはないが答えがない 条件が厳しすぎないか。人と曜日の引数を逆にしていないか

出発ファイルの TODO(作業N) はコメントである。コメントを書き換えるだけでなく、その下へ実行できる規則を書く。未定義のまま問い合わせたときのエラーを、条件を満たす答えがないという確認結果にはしない。

ブラウザを使う場合

教員と確認してSWISHを使う場合は、左のプログラム欄へ配布 .pl の全内容、右下の問い合わせ欄へ質問を一つ入れ、Run! で実行する。変更後も再度 Run! を押す。実行のためのサービス上への保存は必要ない。SWISH公式ヘルプ

SWISHでは端末用の起動コマンドや make. を入力しない。画面の操作はローカルのSWI-Prologと異なるので、授業で使う場合は教員の実演に合わせる。どちらの環境でも、規則と問い合わせの内容、および確認すべき答えの集合は共通である。
