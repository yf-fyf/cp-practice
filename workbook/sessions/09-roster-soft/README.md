# 第09回 勤務表: ソフト制約と公平性（演習ファイル）

考え方・手順・ヒントは教材ページにある。ここには実行方法だけを書く。

## ファイル

| ファイル | 使うところ |
|---|---|
| `roster_soft.mzn` | 必須演習・標準演習・発展演習。`% TODO` が3か所ある |
| `small_pref.dzn` | 基礎データ（4人・3日 + 希望休3件） |
| `week_pref.dzn` | 標準データ（8人・7日 + 希望休） |

第08回の `roster.mzn` を拡張したものである。**ハード制約の3本は書き込んである。**
`.dzn` も第08回のものに希望休 `want_off` と重み `w_pref` `w_fair` `w_night` を
足しただけで、ほかの値は同じである。

`.dzn` はどちらも架空のデータである。実在する職場の希望調査ではない。

## 実行する

手順は5行のカードに1か所だけまとめてある。
教材サイトの参考資料「MiniZinc 実行環境の使い方」の**手順カード（モデル + データ）**を見る。
Playground の画面が変わったときも、直すのはそのカード1か所である。

この回で使うのは次の組み合わせである。

- モデル: `roster_soft.mzn`
- データ: `small_pref.dzn`（必須演習）／ `week_pref.dzn`（標準演習）

**重みを変えるときは `.dzn` の末尾3行を書き換える。** モデルは触らない。

## 出力の読み方

```text
        1日 2日 3日   勤務  夜勤
職員A   *休  夜 *休    1     1
職員B    日  日  日    3     0
職員C    夜 *休  夜    2     2
職員D    日  日  日    3     0
#size 4 3
#shift A ONO
#shift B DDD
#shift C NON
#shift D DDD
```

- `*` は希望休の印である。**`*` の付いたマスが「休」でなければ違反**である
- 右2列はその人の勤務日数と夜勤の回数である
- `#` で始まる行は第10回の検証プログラムが読む行である。**書式を変えないこと**

`% TODO` を埋めて出力のコメントを外すと、
`希望休違反 = ...` の行と `#value ...` の行が増える。

最適化では途中経過の解が何本も表示される。
**最後の1本が最適解**で、末尾の `==========` が「これ以上は無い」という印である。
`==========` が出ないまま止まらないときは、その設定では最適だと
確かめきれていない。教材ページの標準演習の警告を読むこと。

操作の詳細は教材サイトの「MiniZinc 実行環境の使い方」にある。
