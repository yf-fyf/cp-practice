# 第01回の発展・選択演習

予定と技能の関係を深める問題、家系図へ移す問題、再帰と経路を調べる問題を用意した。順番に全部解く必要はなく、関心に合うものを選べる。各問題の出発ファイルは独立しており、別の演習が未完でも始められる。[第01回の本文](lesson.md)と[実行の手引き](guides/prolog-start.md)へ戻れる。

## 選択P01　家系図 {#family}

親子関係を二段たどり、ある人の祖父母に当たる人を調べる。二つの親子関係を「中間の人」で結ぶ問題である。事実・規則・問い合わせの復習から取り組める別題材で、10〜15分を目安にした最初のおすすめである。

### 問題と入力

架空の家系図を調べる。この問題では、`parent(P,C)`{.prolog} を「PはCの親」、`male(P)`{.prolog} と `female(P)`{.prolog} を人物の属性として与える。父は男性属性を持つ親、母は女性属性を持つ親として定義し、下記の全事実だけを使う。

```{.prolog filename="family-start.pl"}
% 架空の家系図。この問題で使う属性と親子関係の全事実。
male(ren).
male(kai).
male(nao).
female(emi).
female(mio).
female(yui).

% parent(親, 子)。
parent(ren, kai).
parent(emi, kai).
parent(ren, mio).
parent(emi, mio).
parent(kai, nao).
parent(yui, nao).
```

::: {.given label="求める関係"}
`father(P,C)`{.prolog} と `mother(P,C)`{.prolog} を定義する。続いて `grandparent(G,C)`{.prolog} を、「Gの子であり、Cの親でもある人がいる」という関係として定義する。GからCへちょうど二段の親子関係をたどり、より遠い祖先は含めない。
:::

### 作業と手掛かり

[family-start.pl](../../../workbook/sessions/01-prolog/family-start.pl)の `TODO(作業1)` に父と母、`TODO(作業2)` に祖父母の規則を書く。候補の名前を規則へ直接書き込まず、与えられた事実と変数から関係を導く。

`father(P,mio).`{.prolog}、`mother(P,nao).`{.prolog}、`grandparent(G,nao).`{.prolog}、`grandparent(ren,C).`{.prolog} を実行する。二段の関係で共有した変数は、答えの引数として外へ出す必要があるかも考えてみよう。

::: {.hint summary="ヒントを開く：親子の矢印の接点"}
Gから中間の人へ、中間の人からCへ、親→子の矢印を二本描く。その接点に同じ変数名を置く。二つの `parent` で、中間の人は異なる位置の引数になる。
:::

作業1で止まった場合は、次の参照例から作業2へ進んでよい。必修1と同じく、属性を持つ人と関係に現れる人が一致するよう、両条件に同じ変数を使っている。

::: {.hint summary="ヒントを開く：父と母の参照例"}
父と母を導く部分は、次の二つの規則になる。これを出発点にして、祖父母の規則を考えてよい。

```prolog
father(P, C) :- male(P), parent(P, C).
mother(P, C) :- female(P), parent(P, C).
```
:::

### 自分の答えの確認

問い合わせの答えは順に `ren`、`yui`、`ren` と `emi`、`nao` となる。最後の二つは、祖父母を求める向きと孫を求める向きを変えて、同じ関係を調べている。

`grandparent(kai,nao).`{.prolog} は成立しない。kaiはnaoの親であり、この入力にはkaiからnaoへ二段でつながる人がいないためである。祖父母の候補ごとに中間の人を指し示し、二本の事実で説明しよう。

## 発展1　別人での役割分担 {#distinct}

火曜と水曜のイベントで、受付と修理を異なる二人に頼みたい。予定と技能から役割分担の候補を求め、「同じ人が両方を担当してもよい」場合と比べよう。

### 問題と出発点

::: {.given label="条件と入力"}
候補は、架空の三人 `aki`・`ben`・`chi`。予定と技能は次の表がすべてである。火曜を `tue`、水曜を `wed` と書く。

| 人 | 参加できる曜日 | 持っている技能 |
|---|---|---|
| `aki` | 火曜・水曜 | 受付・修理 |
| `ben` | 火曜 | 受付 |
| `chi` | 水曜 | 修理 |

次の条件をすべて満たす候補の組を求める。

- 受付候補は、その曜日に参加でき、受付技能を持つ。
- 修理候補は、その曜日に参加でき、修理技能を持つ。
- 両者の曜日は同じで、受付候補と修理候補は別人である。

求める関係は `distinct_pair(P,Q,D)`{.prolog} とする。`P` は受付候補、`Q` は修理候補、`D` は共通の曜日を求める変数で、引数はこの順に並べる。二人の役割を入れ替えた組は区別する。
:::

[distinct-start.pl](../../../workbook/sessions/01-prolog/distinct-start.pl)には、表の全入力と、完成した関係 `pair(P,Q,D)`{.prolog} が入っている。`pair` は「Pが曜日Dに受付へ対応でき、Qが同じ曜日Dに修理へ対応できる」を表す。予定と技能は確かめるが、同じ人の二役も許す。この関係を使って、別人という条件を追加しよう。必要な規則はファイル内に揃っており、このファイルだけで始められる。

### 新しい記法と作業

`dif(P,Q)`{.prolog} は、PとQが異なるという条件を表す。たとえば `dif(aki,ben)`{.prolog} は成立し、`dif(aki,aki)`{.prolog} は成立しない。未確定の変数にも異なるという条件を残せる記法である。[SWI-Prolog公式の説明](https://www.swi-prolog.org/pldoc/doc_for?object=dif/2)

`TODO(作業1)` に、`pair` と `dif` を組み合わせて `distinct_pair(P,Q,D)`{.prolog} を定義する規則を書く。提供された `pair` は残しておき、追加前と追加後の両方を問い合わせられるようにする。

保存して読み込み直したら、問い合わせ欄で `pair(P,Q,D).`{.prolog} と `distinct_pair(P,Q,D).`{.prolog} をそれぞれ実行し、次の答えがなくなるまで調べる。どちらも受付候補・修理候補・曜日をすべて求める問い合わせである。続いて `distinct_pair(aki,aki,tue).`{.prolog} を実行し、火曜にakiを二役へ挙げる組が認められるか確かめよう。操作に迷ったら[実行の手引き](guides/prolog-start.md)を利用できる。

### 自分の答えの確認

二つの問い合わせの答えを、次の表と比べる。各組は受付候補・修理候補・曜日の順に読む。答えが表示される順番は問わない。

| 問い合わせ | 答えの集合 |
|---|---|
| `pair(P,Q,D).`{.prolog} | `(aki,aki,tue)`、`(aki,aki,wed)`、`(aki,chi,wed)`、`(ben,aki,tue)` |
| `distinct_pair(P,Q,D).`{.prolog} | `(aki,chi,wed)`、`(ben,aki,tue)` |

akiを二役に使う火曜・水曜の二組だけが消える。`distinct_pair(aki,aki,tue).`{.prolog} は成立しない。残った二組についても、このブロックの予定と技能の表で、両者の曜日と役割に必要な技能を照合しよう。人名を入れ替えた組も成立するとは限らない。

`P` と `Q` を別の名前で書いたことと、`dif(P,Q)`{.prolog} を条件にしたことは違う。どちらが「別々に値を求める位置」で、どちらが「値が異なる要求」なのかを説明してみよう。

## 発展2　一辺以上の到達 {#reach}

別の題材として、一方通行の道をたどる。直接の道がなくても途中の場所を経由すれば着けることを、関係を使う規則で表してみる。ここからは再帰をこのページ内で学ぶ。

### 問題と入力

::: {.given label="条件と入力"}
場所はa・b・c・dで、有向辺はa→b、a→c、b→d、c→dの四本だけとする。逆向きには進めない。一辺以上をたどってXからYへ到達できる関係 `reach(X,Y)`{.prolog} を定義する。
:::

[reach-start.pl](../../../workbook/sessions/01-prolog/reach-start.pl)には全入力がある。`edge(X,Y)`{.prolog} はXからYへの直接の辺であり、道の向きを入れ替えた別の事実を勝手に補わない。

```prolog
edge(a, b).
edge(a, c).
edge(b, d).
edge(c, d).
```

### 再帰の読み方と作業

再帰とは、ある関係を定義する規則の中で、その関係自体を使うことである。たとえば「少なくとも一回乗り換えて進む」を考える前に、「直接進める場合」を用意すると、続きを短い問題へ分けていける。

記法の小例として、次は「直接の親子関係」と「親から子へ一段進み、そこから祖先関係が続く場合」を書いている。`parent` の事実は親から子の順で、これは再帰の読み方を示す別の例である。

```prolog
ancestor(X, Y) :- parent(X, Y).
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).
```

`reach-start.pl` の `TODO(作業1)` に、直接の場合と、最初の辺で中間の場所へ進む場合を書く。`reach(a,Y).`{.prolog} の答えを最後まで求め、`reach(d,Y).`{.prolog} でも確かめる。

::: {.hint summary="ヒントを開く：最初の一辺と残り"}
XからZへの直接の辺があり、ZからYへ到達できるなら、XからYへも到達できる。中間の場所Zを二つの条件で共有する。直接の場合の規則も必要になる。
:::

### 自分の答えの確認

aからの到達先の集合はb・c・dである。ただしdにはa→b→dとa→c→dの二つの経路があるため、上の小例と同じ形の規則ではdが二度現れる。表示回数と到達先の種類の数を区別しよう。

dから先の辺はないので、`reach(d,Y).`{.prolog} は答えなしとなる。一辺以上という条件なので、移動せずにd自身にいることはこの関係の答えに含めない。この入力では辺をたどると先へ進み、同じ場所へ戻らないため、探索が有限で終わる。

## 発展3　再訪しない経路 {#paths}

一方通行の道でつながった場所をたどり、始点から終点までに通る場所の順序を求める。道には、たどり続けると出発した場所へ戻る循環がある。同じ場所を再訪しない条件を設計し、探索が終わる理由まで考えよう。

### 問題と入力

::: {.given label="条件と入力"}
場所はa・b・c・d、有向辺はa→b、a→c、b→d、c→d、d→aの五本だけとする。`path(Start,Goal,Path)`{.prolog} は、具体的に指定した始点から終点へ辺の向きに進む経路を、場所のリストとして返す関係とする。

同じ場所は一つの経路に二度含めず、始点・終点もこの条件の対象とする。始点と終点が同じときは、移動しない一要素のリストを一経路とする。たとえば `path(a,a,Path).`{.prolog} は `[a]`{.prolog} を返し、一周して戻る経路を含めない。
:::

[path-start.pl](../../../workbook/sessions/01-prolog/path-start.pl)に全入力と `TODO(作業1)` がある。ファイル中の `edge(X,Y)`{.prolog} は、場所Xから場所Yへ直接進める一方向の道を表す。逆向きの道は、別の辺が与えられている場合だけ使える。発展2の完成コードを必要とせず、以下の記法から始められる。問い合わせでは始点と終点を具体的な名前にし、経路の位置を変数にする。

### リストと訪問済み

`[a,b,d]`{.prolog} は三つの要素を順に並べたリスト、`[]`{.prolog} は空のリストである。`[H|T]`{.prolog} は先頭Hと残りのリストTに分ける記法で、`[a,b,d]`{.prolog} と対応させるとHはa、Tは `[b,d]`{.prolog} になる。

| 記法 | この演習で使う意味 |
|---|---|
| `[Next|Seen]`{.prolog} | 訪問済みリストSeenの先頭にNextを加える |
| `member(X,Seen)`{.prolog} | XがSeenの要素である |
| `\+ member(Next,Seen)`{.prolog} | 具体的なNextが、具体的な訪問済みリストSeenにない |
| `reverse(Seen,Path)`{.prolog} | Seenを逆順にしたリストがPathである |

`\+`{.prolog} は、続く問い合わせが成功しないことを調べる記法である。この演習では `edge(Current,Next)`{.prolog} で次の場所を具体的に決めてから、訪問済みかを調べる。未知のNextを先に `\+ member(Next,Seen)`{.prolog} へ渡しても、未訪問の場所を列挙する意味にはならない。

訪問済みを先頭への追加で保持すると、a→b→dをたどった時点のリストは `[d,b,a]`{.prolog} になる。経路として返すときは始点から終点の順に揃える必要がある。先頭への追加以外の管理方法を考えてもよい。

補助関係へ途中のリストを渡す形を、小さい別例で確かめる。次はリストの要素を先頭へ積み、逆順にする関係である。

```prolog
rev_walk([], Acc, Acc).
rev_walk([H|T], Acc, Result) :- rev_walk(T, [H|Acc], Result).
```

`rev_walk([a,b],[],R).`{.prolog}を問い合わせると`R=[b,a]`になる。一つ目の規則は残りが空のとき、積んだリストと結果を同じものにする。二つ目は残りを先頭HとTに分け、HをAccの先頭へ加えて次の呼び出しへ渡す。途中の変数を代入で書き換えるのではなく、次の引数に別の値を渡している。経路では、この役割に現在地・訪問済み・返す経路を対応させる。

### 作業と停止の根拠

現在地・終点・訪問済み・返す経路の役割を決め、必要な補助関係を定義する。始点を訪問済みに入れて始め、「終点に着いた場合」と「未訪問の隣へ進む場合」を分けて書く。

::: {.hint summary="ヒントを開く：一歩ごとの更新"}
終点なら今の経路を返す。先へ進むなら辺を一つ選び、次の場所が未訪問であることを確かめ、訪問済みへ追加して続きを調べる。訪問済みは再帰呼び出しの引数へ渡す。
:::

今回のグラフでは、訪問済みへ追加できる異なる場所は最大四つである。一般の有限グラフでも、再訪を禁じれば、一つの枝で進める回数に上限ができる。一歩ごとに何が増え、その上限がどこから来るかを説明しよう。

### 自分の答えと一般化

`path(a,d,Path).`{.prolog} の答えは `[a,b,d]`{.prolog} と `[a,c,d]`{.prolog} の二経路で、順番は問わない。各リストの隣り合う二要素に辺があり、始点・終点が合い、要素が重複していないことを確かめる。

小さな別の有限グラフでも試そう。到達不能な組、自己ループ、二方向の辺、始点と終点が同じ場合を含め、Pythonなど別の方法で単純経路を全列挙して答えの集合を照合する。辺の同じ事実は重複して入力しないものとする。

比較する到達関係 `reach(X,Y)`{.prolog} は、一辺以上の道をたどってXからYへ着けることを表す。次の規則を経路用のプログラムとは別に保存し、この問題に示した五本の辺を `edge` の事実として加えると試せる。

```prolog
reach(X, Y) :- edge(X, Y).
reach(X, Y) :- edge(X, Z), reach(Z, Y).
```

循環を含むグラフへこの単純な再帰だけを使うと、追加の答えを探し続けて終わらない場合がある。中断方法を確認してから試し、答えがまだ出ないことを「到達不能」と解釈しない。目標の順序を変えたときの違いも、具体例を固定して比較してみよう。
