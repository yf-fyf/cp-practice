# 第15回 成果発表会

## この回の目標

この回を終えると、次のことができる。

- 問題の背景からモデル・結果・検証・限界までを、一貫して説明できる
- コードを読んでいない人に、何を変数にして何を制約にしたかが伝わる話ができる
- 他の人の発表に対して、モデルの前提や検証方法を問う質問を出せる
- 受けた質問に、根拠（実行結果・検証記録）を挙げて答えられる

## 今回やること

成果物一式の提出と、発表・相互質問である。

| 時間 | 活動 |
|---|---|
| 0:00〜0:05 | 開会。進行の説明と成果物の提出確認 |
| 0:05〜0:22 | 発表1（発表10分・質疑4分・入替3分） |
| 0:22〜0:39 | 発表2 |
| 0:39〜0:56 | 発表3 |
| 0:56〜1:13 | 発表4 |
| 1:13〜1:30 | 発表5 |
| 1:30〜1:35 | 全体講評 |
| 1:35〜1:40 | **予備**（延びた分を吸収する） |

::: note
この時間割は**5名を想定した仮案**である。人数が変われば持ち時間も変わる。
確定した時間割は授業中に案内する。

末尾の5分は**予備**である。発表や質疑が延びることを見込んで空けてある。
延びなければ、その5分は全体の質疑にあてる。
:::

### 発表で話すこと

構成は [発表資料の構成ガイド](../projects/presentation-guide.md)にある。
順序は次のとおりで、**この順に話す**。

1. 問題設定（何を決める問題か。背景と入力）
2. モデル（変数・定義域・主要な制約・目的）
3. 使った道具と実行方法
4. 結果（実験の表）
5. 正しさの確認（どう検証したか。何が合格したか）
6. 工夫した点
7. 未解決の点と改善案

::: important
**5 を飛ばさない。**

「動きました」で終わる発表は、この科目では未完成である。
ソルバーが解を返したことと、モデルが正しいことは別だからである。
検証の結果は、うまくいかなかったものも含めて述べる。
「反例が検出できなかった」も立派な報告である。
:::

### 相互質問

各発表につき、**発表者以外は最低1問**を出す。
観点は次の4つで、どれか1つを選べばよい。

| 観点 | 問いの形 |
|---|---|
| **モデルの前提** | 現実にはあるがモデルに入れなかった条件は何か |
| **制約の不足** | この制約を外したら、どんな解が出てしまうか |
| **目的関数の意味** | この目的で「良い」とされる解は、誰にとって良いのか |
| **検証方法** | その検査を通ったことは、何を保証していて何を保証していないか |

::: warning
質問は**モデルに対して**行う。書き方の好みや資料の体裁を問わない。

答えられない質問が出るのは正常である。
「そこは確かめていない」と答えてよい。
**確かめていないことを確かめていないと言えること**が、
第10回から続けてきたことの中身である。
:::

## 扱わないこと

- **成果物の追加作業** → 発表当日は提出済みの版で話す。
  質疑で見つかった不足は、口頭で「今後の課題」として述べる
- **他の人の成果物の公開** → 発表資料とモデルは教材サイトには載せない

## この科目のあと

15回を通じて行ったのは、**解き方の手順ではなく、解が満たすべき条件を書く**
という1つのことである。道具は3つ出てきたが、
[定式化の7手順](../references/modeling-steps.md)はどれでも変わらなかった。

この考え方が効く場面は授業の外にもある。
配置・割当て・日程・組合せの選択、そして「条件を全部満たす例はあるか」を
問いたい場面である。そういう問題に出会ったら、まず7手順で書き下してみる。
書けないなら、まだ問題が決まっていない。
