# 第09回　SATで依存・排他・選択を扱う

アプリにどの機能を入れるかを、真偽値の組として決める。ある機能に別の機能が必要という依存や、同時には選べないという条件を論理式へ写し、すべての条件を満たす選び方を求める。

## 目標 {.unnumbered}

この回では、既習の命題論理を使い、条件を満たす真偽値を計算機に探させる。代入を表示できたら、次の三つを説明できるようになろう。

- 依存・排他・少なくとも一方・ちょうど一方を論理式で表せる。
- SAT・UNSAT・判定不能を区別し、SATの代入を元の条件と照合できる。
- 固定した二つの代入で、「ちょうど一方」の条件漏れを調べられる。

命題論理式・真理値表・論理回路とPythonの基本を使う。Z3の環境操作とAPIは授業内で説明する。[操作用の小例](../../../workbook/sessions/09-sat/warmup.py)、[判定と表示の共通部分](../../../workbook/sessions/09-sat/sat_io.py)、[実行手引き](guides/sat-start.md)から始められる。第08回のPython発展や、MiniZincからの変換は前提にしない。

説明・実演に55分、[5. 演習](#演習)に40分、振り返りに5分を使う。必修1は15分、必修2は20分、残り5分は確認の目安である。環境準備を事前の宿題にはせず、通常演習の提出・宿題・完了報告・教員の完了承認も設けない。発展は選んで取り組む。

## 問題

機能の名前だけから追加の関係を推測せず、ここに示す条件を正式な仕様として読む。どの機能を選ぶかを決定し、選ばれた機能の数を最大にするなどの目的は置かない。

::: {.given label="条件と入力"}
アプリの構成として、次の四機能をそれぞれ選ぶか選ばないか決める。

| 記号 | 機能 |
|---|---|
| A | 分析画面 |
| B | 集計機能 |
| C | データ保存機能 |
| D | 保存しない動作モード |

守る条件は次の四つである。

1. Aを必ず選ぶ。
2. Aを選ぶならBも選ぶ。
3. Bを選ぶならCも選ぶ。
4. CとDを同時には選ばない。

これらをすべて満たす一つの選び方を求める。真は選ぶこと、偽は選ばないことを表す。
:::

「AにはBが必要」は、Bを選んだら必ずAも選ぶという意味ではない。また「CとDを同時には選ばない」は、必ずどちらかを選ぶという意味ではない。必要な関係を一つずつ分けて表そう。

## 定式化

まず、各機能を選ぶかどうかへBoolean変数を対応させる。その上で、問題文の四条件を論理式へ写す。式の真偽を調べる代入を自分で決める場合と、式を真にする代入を探す場合を区別しよう。

### 充足可能性と代入

Boolean変数は真または偽を値に持つ。A・B・C・Dへ値を割り当てることを**代入**と呼ぶ。四変数なら代入は $2^4=16$ 通りあり、各代入について問題の式が真か偽かを調べられる。

式を真にする代入が一つでも存在するかという問題を、**充足可能性問題（SAT）**と呼ぶ。存在すればSAT、どの代入でも満たせなければUNSATである。すべての代入で真かを調べることとは異なる。

今回はZ3というソルバーをPythonから使う。Z3は整数などを含む問題も扱えるが、この回で渡す条件は命題論理の範囲である。整数の時刻を含める問題は第10回で扱う。

### 依存と排他

Aを選ぶならBも選ぶという依存を $A\Rightarrow B$ と書く。この式が偽になるのは、Aが真なのに必要なBが偽という場合だけである。Aが偽なら、この条件はBを制限しない。

| A | B | A⇒B | ¬A∨B |
|---|---|---|---|
| 偽 | 偽 | 真 | 真 |
| 偽 | 真 | 真 | 真 |
| 真 | 偽 | 偽 | 偽 |
| 真 | 真 | 真 | 真 |

一方、CとDの同時選択を禁止する式は $\neg(C\land D)$ である。両方真の場合だけを拒否するので、両方偽でもこの式を満たす。依存と排他は、それぞれどの組を拒否するかで読める。

四条件をすべて守るには、次の連言を真にする。Aという式を単独で加えることが、Aを必須にする指定である。含意だけを書いても、Aそのものを選ぶ義務は生まれない。

$$\Phi=A\land(A\Rightarrow B)\land(B\Rightarrow C)\land\neg(C\land D).$$

### 記号式とPythonの真偽値

`Bool('A')`{.python}は、まだ値を決めていない記号としてのAを作る。Pythonの変数名Aへ`True`{.python}を代入する操作ではない。依存などの式をソルバーへ渡した後、条件に合うAの値を求める。

| 論理の意味 | Z3へ渡す式 |
|---|---|
| AかつB | `And(A, B)`{.python} |
| AまたはB | `Or(A, B)`{.python} |
| Aではない | `Not(A)`{.python} |
| AならばB | `Implies(A, B)`{.python} |

未知の記号式をPythonの`and`{.python}・`or`{.python}・`not`{.python}で結んだり、`if A:`{.python}で分岐したりしない。Python自身が真偽を決めようとして、エラーや意図と異なる式の原因になる。確定した通常のboolを扱う真理値表とは場面を分けよう。

## 解説例

教員が操作例から始め、変数を作り、条件を加え、判定と代入を読む。配布ファイルにはインポートと実行部分もあり、新しいAPIは問題の式との対応を見ながら確認できる。

### 手順1　Boolean変数

まず[warmup.py](../../../workbook/sessions/09-sat/warmup.py)を実行し、SATとp・qの値を読む。条件は`Or(p, q)`{.python}なので、少なくとも一方がTrueになればよい。次に[features-demo.py](../../../workbook/sessions/09-sat/features-demo.py)の四機能の宣言を見る。

```{.python filename="features-demo.py"}
    A = Bool('A')
    B = Bool('B')
    C = Bool('C')
    D = Bool('D')
```

各行の左側はPythonで使う名前、`Bool`の文字列はZ3の記号名である。同じ名前の記号を誤って複数の機能へ使わない。配布ファイルの`build`関数は、新しいソルバーと変数の対応を作って返す足場である。

### 手順2　依存と排他

`Solver()`{.python}で条件を入れるソルバーを作る。`s.add`へ複数の式を渡すと、そのすべてを満たすように要求する。依存二つと、C・Dの同時選択の禁止を順に追加する。

```{.python filename="features-demo.py"}
    s = Solver()
    s.add(Implies(A, B), Implies(B, C), Not(And(C, D)))
```

通常の実行では、さらに`s.add(A)`{.python}でAを必須にする。ここまでが問題文の四条件に対応する。選ぶ数を増やす、依存の逆も成り立たせるなど、書かなかった条件はソルバーが補うものではない。

### 手順3　判定と代入の確認

[sat_io.py](../../../workbook/sessions/09-sat/sat_io.py)の`report`が、判定結果を三つの場合に分ける。`check()`{.python}は充足可能性の判定であり、SATの場合にだけ`model()`{.python}から一つの充足代入を読む。

```{.python filename="sat_io.py"}
    result = solver.check()
    if result == sat:
        values = read_values(solver.model(), variables)
        print('SAT')
```

ここでZ3が返す**モデル**は、条件を満たす代入のことである。問題を表現するプログラム全体を「モデル」と呼ぶ用法とは、読む場面が異なる。配布の表示処理は、指定した全変数の真偽を順番に出す。

```sh
python3 features-demo.py
```

出力を次の[結果](#結果)と照合する。UNSATでは充足代入を表示せず、UNKNOWNなら判定できなかった理由を表示する。判定不能を解なしへ読み替えず、SATでないときにモデルを取り出さない。

### 手順4　条件の追加と削除

同じ解説例でDも必須にした場合と、最初のA必須だけを外した場合を別々に試す。各コマンドは新しいソルバーから実行するので、前の実行で加えた条件が残ることはない。

```sh
python3 features-demo.py --case with-D
python3 features-demo.py --case without-A
```

Dも必須にすると、AからB、BからCが必要になり、CとDの排他と衝突する。A必須を外すと、全機能を選ばない代入も許される。ただし、複数ある代入のうち、必ず全偽が表示されるという意味ではない。

## 結果

通常の四条件を満たす代入は一つである。Aが必須なので真、依存を順にたどるとBとCも真となる。CとDを同時に選べないためDは偽になる。この推論を実出力と照合しよう。

```text
SAT
A=True
B=True
C=True
D=False
```

A・B・Cが真で依存を満たし、Dが偽で共存禁止を満たす。一つの式だけでなく、問題の四条件をそれぞれ確認する。Dも必須にした実行はUNSATになる。

| 実行 | 判定 | 条件からの説明 |
|---|---|---|
| 通常 | SAT | A・B・Cが真、Dが偽 |
| Dも必須 | UNSAT | 必須となるCとDが共存できない |
| A必須を削除 | SAT | 全偽も許される。表示される一例は他でもよい |

含意は真理値表のとおり $A\Rightarrow B\equiv\neg A\lor B$ と書ける。同様に式Φを、次のような「または」のまとまりを「かつ」でつないだ形へ書き換えられる。

$$A\land(\neg A\lor B)\land(\neg B\lor C)\land(\neg C\lor\neg D).$$

変数またはその否定を**リテラル**、リテラルの論理和を**節**、節の連言を**CNF（連言標準形）**と呼ぶ。Aだけの節もある。この形は発展の小さいSATソルバーやMaxSATで再び使う。必修では、CNFへの一般変換やファイル形式を自作せず、Z3へ式を渡せばよい。

n変数なら代入は $2^n$ 通りある。条件から確定できる値を進め、未定なら場合分けする考え方は第03回とつながる。ただし、実際のZ3がすべてを単純な真理値表の順で調べると説明しているわけではない。小さい学習用の探索は発展で扱う。

## 演習

必修1では依存・排他・必須の指定を自分で書き、必修2では一つの選択条件を二つの式へ分ける。どちらも出力の足場は提供するので、問題の条件と追加する式の対応に集中しよう。

### 必修1　必須機能の変更

五つの機能から、履歴閲覧を必ず使える組合せを選ぶ。ある機能を使うなら別の機能も必要になるという依存と、必ず使う機能の指定を、別々に式へ表す。

#### 問題

::: {.given label="条件と入力"}
A＝分析画面、B＝集計機能、C＝データ保存機能、D＝保存しない動作モード、E＝履歴閲覧機能を、それぞれ選ぶか選ばないか決める。守る条件は次の五つ。

1. Eを必ず選ぶ。Aには必須指定を置かない。
2. 履歴を見るにはデータ保存が必要である。
3. 分析画面を使うには集計機能が必要である。
4. 集計機能を使うにはデータ保存が必要である。
5. データ保存と、保存しない動作モードは共存できない。

真は選ぶこと、偽は選ばないことを表す。以上をすべて満たす一つの代入を求める。目的関数は置かない。
:::

#### 作業

[features-start.py](../../../workbook/sessions/09-sat/features-start.py)と[sat_io.py](../../../workbook/sessions/09-sat/sat_io.py)を同じフォルダーへ保存する。変数宣言、ソルバーの作成、判定と表示の足場は完成している。A〜Eは問題の機能に対応するZ3のBoolean変数で、`s` は条件を保持するソルバー、`s.add(...)`{.python} は条件を追加する操作である。条件をTODOへ追加する。

1. **作業1：** 必須のEと、EからCへの依存を式にして追加する。
2. **作業2：** AからB、BからCへの依存、CとDの共存禁止を追加する。
3. 実行し、SATなら各変数の値が五条件を満たすか確認する。

```{.python filename="features-start.py"}
    # TODO(作業1): 必須はEとし、EからCへの依存を追加する。
    # TODO(作業2): AからB、BからCへの依存と、C・Dの共存不可を追加する。
```

出発ファイルは未記入でも実行できるが、その場合は問題の条件が足りない。SATと表示されることだけで完成とはせず、どの`s.add`がどの条件に対応するかを読み直そう。

#### 自己確認

CとEは真、Dは偽である。AとBは次の三通りのいずれかになればよい。一回の実行で一つが得られればよく、必修で全代入の列挙は要求しない。

| A | B | C | D | E |
|---|---|---|---|---|
| 偽 | 偽 | 真 | 偽 | 真 |
| 偽 | 真 | 真 | 偽 | 真 |
| 真 | 真 | 真 | 偽 | 真 |

Aが偽でBが真でも、AならばBという依存を満たす。Aが必ず真になる制約を残すと、正しい選択肢を狭めてしまう。出力がたまたまA真だったことだけでは、その余分な制約がないとは確認できない。

次は自分のモデルに値を固定して、余分な条件と条件漏れを検査する。配布フォルダで次を実行する。`--case`は各回新しいモデルに固定値を追加する操作で、TODOへ書いた条件はそのまま使う。

```sh
python3 features-start.py --case A-false
python3 features-start.py --case A-without-B
python3 features-start.py --case E-without-C
```

| 検査 | 固定値（A・B・C・D・Eの順） | 期待 |
|---|---|---|
| A-false | 偽・真・真・偽・真 | SAT |
| A-without-B | 真・偽・真・偽・真 | UNSAT |
| E-without-C | 偽・偽・偽・偽・真 | UNSAT |

最初の例はAを必須にする誤りや含意の逆転、後の二例は依存の欠落・逆転を調べる。UNKNOWNやエラーは期待したUNSATとは違う。検査後も、五条件がすべて書かれているかを読み返す。

::: {.hint summary="ヒントを開く：拒否したい代入を考える"}
「Eが必須」と「EにはCが必要」について、それぞれ破る代入を一つ書く。後者はEが偽のときもCを強制する条件かを考える。残りの依存と共存禁止も、どの真偽の組を拒否するかで確かめよう。
:::

::: {.hint summary="ヒントを開く：確認例・必須と依存の式"}
`s.add(E, Implies(E, C))`{.python}で最初の二条件を加える。残りは`Implies(A, B)`{.python}、`Implies(B, C)`{.python}、`Not(And(C, D))`{.python}である。依存の矢印の向きと、A必須を加えていないことを確認する。
:::

### 必修2　二機能のちょうど一方

新しい表示機能Fを加え、Aとの選択を決める。Fには別の依存や禁止がないので、「少なくとも一方」と「両方は不可」のどちらを欠いても、不適切な代入が許されることを確認できる。

#### 問題

::: {.given label="条件と入力"}
A＝分析画面、B＝集計機能、C＝データ保存機能、D＝保存しない動作モード、E＝履歴閲覧機能、F＝追加の表示機能を、それぞれ真偽で選ぶ。

1. Eを必ず選ぶ。Aには必須指定を置かない。
2. 履歴を見るにはデータ保存が必要である。
3. 分析画面を使うには集計機能が必要である。
4. 集計機能を使うにはデータ保存が必要である。
5. データ保存と、保存しない動作モードは共存できない。
6. AとFのちょうど一方を選ぶ。

Fには条件6以外の依存・必須指定・排他はない。真は選ぶこと、偽は選ばないことを表す。以上をすべて満たす一つの代入を求め、目的関数は置かない。
:::

#### 作業

[exclusive-start.py](../../../workbook/sessions/09-sat/exclusive-start.py)、完成した[features_base.py](../../../workbook/sessions/09-sat/features_base.py)、[sat_io.py](../../../workbook/sessions/09-sat/sat_io.py)を使う。条件1〜5とFの宣言は提供済みなので、必修1の完成を待たずに始められる。A〜Fは問題の機能に対応するZ3のBoolean変数で、`s.add(...)`{.python} に追加する式がソルバー `s` の条件になる。

1. **作業1：** AとFの少なくとも一方を選ぶ式を追加する。
2. **作業2：** AとFを両方選ぶことを禁止する式を追加する。
3. 通常の問題を実行した後、二つの固定値の検査を別々に実行する。

```{.python filename="exclusive-start.py"}
    # TODO(作業1): AとFの少なくとも一方を選ぶ条件を書く。
    # TODO(作業2): AとFを両方選ぶことを禁止する条件を書く。
```

固定値の検査は、完成した元の問題にAとFの値を追加して調べる。各コマンドが新しいソルバーを作るので、両方真の条件と両方偽の条件を一つの問題に積み重ねない。

```sh
python3 exclusive-start.py
python3 exclusive-start.py --case both-true
python3 exclusive-start.py --case both-false
```

#### 自己確認

通常はSATで、CとEが真、Dが偽になる。残る(A,B,F)は次の三通りのどれかでよい。AとFを選ぶ条件が、Bへの依存を消していないことも確認しよう。

| A | B | F |
|---|---|---|
| 真 | 真 | 偽 |
| 偽 | 偽 | 真 |
| 偽 | 真 | 真 |

`both-true`と`both-false`は、正しい条件ならどちらもUNSATとなる。両方真が通るなら同時選択の禁止、両方偽が通るなら少なくとも一方の指定を確かめる。元の通常問題がSATであることと合わせて確認する。

| A | F | ちょうど一方として許すか |
|---|---|---|
| 偽 | 偽 | 許さない |
| 偽 | 真 | 許す |
| 真 | 偽 | 許す |
| 真 | 真 | 許さない |

この四行の真理値表は、二つの式を組み合わせる意味を確認するもの。固定値の検査は、式を実際の問題全体へ追加できているかを確認するもの。二つの確認を対応させよう。

::: {.hint summary="ヒントを開く：片方の条件だけならどうなるか"}
「少なくとも一方」だけを書いたときと、「両方は不可」だけを書いたときで、上の四行のどれを余分に許すかを調べる。二つの固定検査が、どちらの条件漏れを見つけるかも対応させよう。
:::

::: {.hint summary="ヒントを開く：確認例・拒否する二つの組の式"}
両方偽を除くのが`Or(A, F)`{.python}、両方真を除くのが`Not(And(A, F))`{.python}である。`s.add`へ両方を追加する。Fとの排他を、CとDの既存条件が代わりに保証することはない。
:::

## 振り返り

一つの代入を見つけるだけでなく、その代入がどの条件を満たすかを説明しよう。さらに、条件を追加・削除した結果から、自分が書いた式の役割を確かめられる。

- A⇒BとB⇒Aは、どの代入で違いが表れるか。
- 条件をまだ書いていないプログラムがSATでも、問題を解いたとは言えないのはなぜか。
- 「ちょうど一方」の二成分を、どの固定値で別々に確かめたか。

第10回は同じPythonとZ3を使い、整数の開始時刻へ変数を広げる。今回の全解列挙や探索器の完成は前提にしない。まずは[必修2](#演習)の通常実行と二つの検査を説明できるか確認しよう。

## 参照 {.unnumbered}

操作で迷ったら[Z3の実行手引き](guides/sat-start.md)の環境確認、配布ファイルの組、状態の読み方へ戻る。コードの読み直しには、次の対応を使える。

| 名前・用語 | 意味 |
|---|---|
| `Bool` | 真偽値を求めるための記号を作る |
| `Solver`／`add` | 条件を入れるソルバー／条件の追加 |
| `check` | 充足可能性の判定 |
| SAT／UNSAT | 充足代入が存在する／存在しない |
| UNKNOWN | 判定が得られなかった状態 |
| `model` | SATの場合に得られる一つの充足代入 |
| リテラル・節・CNF | 変数または否定・その論理和・節の連言 |

未知の記号をPythonの真偽値として分岐させる、含意の向きを逆にする、古いA必須を残す、二つの固定検査を重ねる、といった点を確認する。実行時のエラーと、条件の書き間違いによるSAT・UNSATを区別する。

APIの説明は[Z3の公式Python API](https://z3prover.github.io/api/html/namespacez3py.html)、判定は[Solverの公式参照](https://z3prover.github.io/api/html/classz3py_1_1_solver.html)、代入の読み取りは[ModelRefの公式参照](https://z3prover.github.io/api/html/classz3py_1_1_model_ref.html)で確認できる。
