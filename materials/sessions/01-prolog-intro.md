# 第01回 小型論理グリッド: 宣言的に関係を書く

::: {.important}

## この回の目標

この回を終えると、次のことができる。

- 分かっていることを**事実**として正しい構文で書き、実行ページに読み込ませられる
- 変数を含むクエリで問い合わせ、成功・失敗と変数の値を読める
- 2つの条件を「かつ」でつないだ**規則**を書き、事実から新しい関係を導ける
- 同じ探しものを Python で書いた場合と Prolog で書いた場合の違いを、
  「何を書いたか」で説明できる

前提は、論理回路（AND・OR・NOT）程度の論理の知識と、Python を書いた経験だけである。
**Prolog の知識は仮定しない。** この回が初めてで構わない。

## 今回解く問題

架空のサークル名簿がある。4人について、飲み物の好み・所属サークル・通学手段が分かっている。

| 名前 | 飲み物 | サークル | 通学手段 |
|---|---|---|---|
| aoi | cocoa | photo | bicycle |
| hikaru | coffee | tennis | train |
| tsubasa | tea | brass_band | walk |
| kaede | cocoa | photo | train |

::: note
登場する名前・サークル・属性はすべてこの科目のために作った架空のものである。
実在の人物や団体とは関係がない。
:::

この表に対して、次のような問いに答えたい。

- テニス部にいるのは誰か
- ココアを飲む人は、どうやって通学しているか
- 同じサークルに所属している2人は、誰と誰か

表を目で追えば答えられる。ここでやりたいのは、そこではない。
**この表を機械に渡し、問いのほうも機械に渡して、答えを機械に出させる。**
しかも「どう探すか」は一切書かずに済ませる。それが Prolog の書き方である。

## 変数・定義域・制約・目的へ分解

この科目では、どの問題も「変数・定義域・制約・目的」の4語に分解して書く。
ただし**この回ではまだその語彙を使わない**。第01回で扱う問題には、
機械に決めてもらうもの（変数）が無いからである。表の中身は最初から全部分かっている。

代わりに、この回は次の3つに分けて考える。

| 分けかた | この回では | Prolog で書くもの |
|---|---|---|
| 分かっていること | 表の各行の内容 | **事実** |
| 分かっていることから導けること | 「同じサークルの2人」など | **規則** |
| 知りたいこと | 「テニス部は誰か」など | **クエリ** |

第02回で「まだ決まっていないもの」が登場し、第03回でそれを
**変数・定義域・制約**という語彙で呼び直す。
いまは「分かっていること」と「問い」を分けて書く、という点だけを押さえる。

::: {.term}
[**宣言的な記述**](../references/glossary.md#declarative_description)とは、
解を求める**手順**ではなく、成り立っている**関係**を書く書き方である。
「どう探すか」は処理系に任せる。
手順を上から並べる書き方（Python のような**手続き的な記述**）と対になる。
:::

## 概念と構文

### 事実

分かっていることを1行ずつ、次の形で書く。

```{.prolog filename="事実の書き方"}
drinks(aoi, cocoa).
```

「`aoi` は `cocoa` を飲む」と読む。読み方はこちらが決めてよい。
Prolog にとっては「`drinks` という名前の関係が `aoi` と `cocoa` の間に成り立つ」
という以上の意味はない。

形の決まりは2つだけである。

- 名前のうしろに、丸括弧で対象を並べる
- **行の終わりに必ずピリオド `.` を打つ**

::: {.term}
事実を集めたものを [**知識ベース**](../references/glossary.md#knowledge_base)という。
Prolog のプログラムは知識ベースそのものであり、
プログラムを「実行する」とは、この知識ベースに問い合わせることである。
:::

### アトムと変数

Prolog では、**先頭の文字が小文字か大文字か**で意味が変わる。これが最初の関門である。

| 書き方 | 種類 | 意味 |
|---|---|---|
| `aoi` `cocoa` `brass_band` | [アトム](../references/glossary.md#atom) | それ自身を表す固有の名前 |
| `X` `Drink` `Who` | [変数](../references/glossary.md#prolog_variable) | 値がまだ決まっていない名前 |
| `_` | 無名変数 | 「何でもよい」 |

`aoi` と `Aoi` は別物である。前者は「あおいという名前」、
後者は「まだ決まっていない何か」である。

::: warning
うっかり `Aoi` と大文字で書くと、エラーにはならずに
「何でも当てはまる」という意味になってしまう。
結果が妙に多いときは、まずここを疑う。
:::

### 述語

`drinks(aoi, cocoa).` の `drinks` を、この関係の名前という。
関係の名前と引数の個数の組を [**述語**](../references/glossary.md#predicate)と呼び、
`drinks/2` のように「名前/引数の個数」で書く。

**名前が同じでも引数の個数が違えば別の述語**である。
`club/2`（誰がどのサークルか）と `club/1`（サークルの名前）は無関係な2つの述語になる。

### クエリ

知識ベースへの問い合わせを [**クエリ**](../references/glossary.md#query)という。
実行ページのクエリ欄に1行で書く（末尾のピリオドは省略してよい）。

| クエリ | 何を聞いているか |
|---|---|
| `drinks(aoi, cocoa)` | それは成り立つか（はい・いいえ） |
| `drinks(aoi, X)` | `aoi` は何を飲むか |
| `drinks(X, cocoa)` | ココアを飲むのは誰か |
| `drinks(X, Y)` | 誰が何を飲むか（全部） |

**同じ事実の並びに、どの位置を変数にするかを変えるだけで違う問いになる。**
Python なら「名前から飲み物を引く」関数と「飲み物から名前を引く」関数を
別々に書くところである。

### 規則と連言

事実から新しい関係を導くのが [**規則**](../references/glossary.md#rule)である。

```{.prolog filename="規則の書き方"}
% X と Y が同じサークル C に所属していれば、2人は teammate である
teammate(X, Y) :- club(X, C), club(Y, C).
```

- `:-` は「ならば」を右から左に書いたものである。「右が成り立てば左も成り立つ」と読む。
- `,` は [**連言**](../references/glossary.md#conjunction)、つまり「かつ」である。
- `%` から行末まではコメントで、日本語を書いてよい。

同じ変数 `C` を2か所に書いたことが効いている。
**同じ名前の変数は、同じ値でなければならない。**
これで「2人のサークルが一致している」が表せる。

::: {.note}
規則の変数は「すべての `X`・`Y`・`C` について」と読む約束になっている。
1行しか書いていないのに誰について問い合わせても答えが返るのはこのためである。
この読み方は番外の自習ページ
[論理の入門(1)](../references/logic-intro.md#prolog-rules)にまとめてある。
:::

### Python と並べてみる

「ココアを飲んでいて写真部の人」を探す処理を、両方の書き方で並べる。
Python のコードは**読むだけ**でよい。書かなくてよい。

```{.python filename="手続き的に書くと（読むだけ）"}
drinks = {"aoi": "cocoa", "hikaru": "coffee", "tsubasa": "tea", "kaede": "cocoa"}
clubs = {"aoi": "photo", "hikaru": "tennis", "tsubasa": "brass_band", "kaede": "photo"}

for name in drinks:
    if drinks[name] == "cocoa" and clubs[name] == "photo":
        print(name)
```

```{.prolog filename="宣言的に書くと"}
drinks(X, cocoa), club(X, photo)
```

答えは同じである。違うのは**書いたもの**である。

| 書いたもの | Python | Prolog |
|---|---|---|
| 探す対象 | `for name in drinks` と自分で書いた | 書いていない |
| 順番に見ていく手順 | 自分で書いた | 書いていない |
| 満たすべき条件 | `if` の中に書いた | これだけ書いた |
| 結果の集め方 | `print` で自分で出した | 書いていない |

Prolog 側に残ったのは**条件だけ**である。
「候補を1つずつ試して、条件に合ったものを返す」という部分は、
書かなくても処理系がやる。これがこの科目の出発点である。

::: important
この「条件だけを書いて、探すのは処理系に任せる」という形は、
第03回以降の MiniZinc・Z3 でも変わらない。
道具は変わるが、**書くものの性質は最後まで同じ**である。
:::

## 小さな実行例

実際に動かす。実行ページを開き、プログラム欄に次を貼る。

```{.prolog filename="飲み物の事実だけ"}
% 好きな飲み物（架空のデータ）
drinks(aoi, cocoa).
drinks(hikaru, coffee).
drinks(tsubasa, tea).
drinks(kaede, cocoa).
```

クエリ欄に `drinks(aoi, X)` と書いて「実行」を押すと、結果欄にこう出る。

```text
解 1: X = cocoa.
```

「次の解」を押すと、これ以上は無いことが分かる。

```text
false.
  → これ以上の解はありません。
```

::: {.term}
`false.` は**間違いという意味ではない**。
「条件を満たすものが（もう）見つからない」という報告である。
Prolog を使っていると常に出るものなので、慣れておく。
:::

`drinks(X, cocoa)` に変えると、今度は該当者が2人いる。
「実行」で1人目、「次の解」で2人目が出る。

```text
解 1: X = aoi.
解 2: X = kaede.
false.
```

::: note
この回の知識ベース（4人分の3属性すべてと `teammate/2` の規則）と
試すクエリの一覧は、実行ページのサンプルに入っている。
[事実と規則のサンプルを読み込んだ状態で実行ページを開く](../../tools/prolog/?example=facts)。
必須演習を自分で書き終えてから、答え合わせに使うとよい。
:::

## 予想してから試す

::: {.predict}
上の知識ベースに、次の3行を足したとする。

```{.prolog filename="足す事実"}
club(aoi, photo).
club(hikaru, tennis).
club(tsubasa, brass_band).
```

そのうえでクエリ `drinks(X, cocoa), club(X, photo)` を実行すると、何が起きると思うか。
次のどれかを選び、理由も書き出してから実行する。

1. `X = aoi.` が出て、「次の解」で `X = kaede.` が出る
2. `X = aoi.` だけが出て、「次の解」では `false.` になる
3. すぐに `false.` になる
4. エラーになる
:::

答えは 2 である。`kaede` は確かにココアを飲むが、
**`club(kaede, photo).` をまだ書いていない**ので、後半の条件が満たせない。

ここが Prolog の重要な性質である。
**書いていないことは「偽」として扱われる。**
「kaede のサークルは分からない」と「kaede は写真部ではない」を
Prolog は区別しない。知識ベースに無いものは、成り立たないものになる。

::: {.check}
ここまでで、次を確認しておく。

- 事実を4行書いて読み込ませ、クエリで値を取り出せた
- 「次の解」を押すと `解 2:` が出るか `false.` になるかを見た
- `false.` がエラーではないと説明できる
:::

## 必須演習

::: {.exercise level=required}
### 名簿を知識ベースにして問い合わせる

`workbook/sessions/01-prolog-intro/kb.pl` を実行ページのプログラム欄に貼り、
`% TODO(1)` と `% TODO(2)` の2か所を埋める。埋める内容は
「今回解く問題」の表にある、4人分のサークルと通学手段である。

```{.prolog filename="kb.pl（抜粋）"}
% 好きな飲み物
drinks(aoi, cocoa).
drinks(hikaru, coffee).
drinks(tsubasa, tea).
drinks(kaede, cocoa).

% TODO(1) 所属サークルの事実を4人分書く。述語の名前は club とする
```

書けたら、次の3つのクエリを順に実行する。

| クエリ | 何を聞いているか |
|---|---|
| `club(X, tennis)` | テニス部にいるのは誰か |
| `drinks(X, cocoa), commute(X, M)` | ココアを飲む人の通学手段は何か |
| `commute(X, train), club(X, C)` | 電車で通う人はどのサークルか |

**完了条件**: 3つのクエリすべてが実行でき、`false.` になるまで
「次の解」を押した結果が、「今回解く問題」の表と一致している。
2番目のクエリでは解が2つ出る。
:::

::: {.hint summary="ヒント1: 1行の形を思い出す"}
事実は `述語名(対象1, 対象2).` の形である。
名前もサークル名も小文字で始まっているので、そのままアトムとして書ける。
行の終わりのピリオドを忘れない。

`drinks(aoi, cocoa).` を眺めて、`drinks` を `club` に、
`cocoa` をサークル名に置き換えれば1行できる。
:::

::: {.hint summary="ヒント2: 引数の順序を決める"}
`drinks(aoi, cocoa)` は「誰が・何を」の順に書いてある。
`club` と `commute` も同じ順（誰が・何を）に揃えると、
クエリを書くときに迷わない。

順序を逆にしても Prolog は動くが、そのときは
`club(tennis, X)` のようにクエリ側も逆にしなければならない。
**表の見出しの順に揃える**のが安全である。
:::

::: {.hint summary="ヒント3: 解答"}
```{.prolog filename="kb.pl（TODO(1) と TODO(2)）"}
% TODO(1) 所属サークル
club(aoi, photo).
club(hikaru, tennis).
club(tsubasa, brass_band).
club(kaede, photo).

% TODO(2) 通学手段
commute(aoi, bicycle).
commute(hikaru, train).
commute(tsubasa, walk).
commute(kaede, train).
```

実行結果は次のようになる。

```text
club(X, tennis)                    → X = hikaru.  そのあと false.
drinks(X, cocoa), commute(X, M)    → X = aoi, M = bicycle.
                                     X = kaede, M = train.  そのあと false.
commute(X, train), club(X, C)      → X = hikaru, C = tennis.
                                     X = kaede, C = photo.  そのあと false.
```
:::

## 標準演習

::: {.exercise level=standard}
### 事実から新しい関係を導く規則を書く

`workbook/sessions/01-prolog-intro/rules.pl` には、必須演習で完成させたものと
同じ知識ベースが入っている。ここに規則を2つ書き足す。

**A. `ride_together/2`** — 同じ通学手段で通う2人を表す規則。
`ride_together(X, Y)` を実行すると、そういう2人の組がすべて出るようにする。

**B. `train_tennis/1`** — 電車で通っていて、かつテニス部にいる人を表す規則。
条件が2つあり、それぞれ別の述語を使う。

**完了条件**: `ride_together(X, Y)` で組が出て、`train_tennis(X)` で `X = hikaru.` が出る。
どちらも `false.` になるまで「次の解」を押し、出てきた組を表と照合できている。
:::

::: {.discuss}
`ride_together(X, Y)` を実行すると、`X = aoi, Y = aoi.` のように
**同じ人どうしの組**が答えに出てくるはずである。

- なぜ出てくるのか。書いた規則のどこがそうさせているのか
- 「同じ人どうしは除きたい」と思ったとき、いまの道具立てで書けるか

書けなくてよい。「等しくない」を表す書き方は第02回で導入する。
いまは**なぜ出るのか**を説明できるところまでで十分である。
:::

::: {.hint summary="ヒント1: どの述語を2回使うか"}
A は「2人の通学手段が一致している」ことを言いたい。
一致を表すには、**同じ名前の変数を2か所に書く**。
`teammate/2` が `club(X, C), club(Y, C)` と書いていたのと同じ形である。

B は条件が2つだが、使う述語は `commute` と `club` で別々である。
2つの条件をつなぐのは `,` である。
:::

::: {.hint summary="ヒント2: 規則の頭部に何を書くか"}
`:-` の左（頭部）には、**外から問い合わせたい形**を書く。

- A は2人の組を聞きたいので、引数は2つ（`ride_together(X, Y)`）
- B は1人を聞きたいので、引数は1つ（`train_tennis(X)`）

頭部に書いた変数が、条件のどこに現れるかを確かめる。
頭部にあって条件に一度も出てこない変数があれば、その規則は何も絞っていない。
:::

## 発展演習

::: {.exercise level=advanced}
### いずれか1つを選ぶ

**A. 事実を足して答えの変化を見る**

5人目 `minori` を名簿に加える。飲み物・サークル・通学手段を自分で決めて事実を3行足し、
必須演習の3つのクエリと標準演習の `ride_together/2` を**足す前と後で**実行し、
答えがどう変わったかを記録する。

考えどころは「どの事実を足すと、どのクエリの答えが増えるか」である。
足した事実と、増えた答えの対応を説明できるようにする。

**B. 答えが1つも出ない状況を作る**

事実は一切消さずに、**クエリの書き方だけで** `false.` になる問い合わせを3通り作る。
そのうえで、3つが `false.` になる理由がそれぞれ違うように選ぶ。
（たとえば「該当者がいない」「述語の名前が違う」「引数の個数が違う」など。）

エラーになるものと `false.` になるものの区別が付くようになるのが狙いである。

**C. 表を縦に読む**

「サークルごとに所属者を並べる」ような、表を縦方向に見る問いを
クエリで書けるか試す。書けない場合、何が足りないのかを言葉で書き出す。
第02回でその道具（リスト）を導入する。
:::

## よくある誤り

| 症状 | 原因 | 直し方 |
|---|---|---|
| `syntax_error(...)` と `line(N)` が出る | N 行目のピリオドを打ち忘れた | 事実も規則も、1つの**行（節）**がピリオドで終わる |
| 同じく `syntax_error` | 全角の `（` `，` `．` や全角スペースが混ざっている | 記号はすべて半角にする |
| `existence_error(procedure, club/2)` | その述語が1つも定義されていない。綴り違いが多い | 名前の綴りと引数の個数を確かめる |
| 何を聞いても `false.` になる | 事実を書いた述語名と、クエリの述語名が違う | プログラム欄とクエリ欄の綴りを見比べる |
| 答えが妙にたくさん出る | 定数のつもりで書いた名前が大文字始まりになっていた | `Cocoa` ではなく `cocoa` と書く |
| 頭部に書いた変数が答えに出てこない（`Y` が表示されない） | 条件のどこにも現れない変数を頭部に書いた | その変数を使う条件を足す |
| 答えが1つ出たあと「次の解」が押せない | 実行が終わっていない、または解が1つも無い | 状態表示を見る。`false.` が出ていれば探索は終わっている |

::: warning
**書いていないことは「偽」になる。**
`club(kaede, photo).` を書き忘れると、Prolog は
「kaede は写真部ではない」と答える。「分からない」とは言わない。
答えが期待より少ないときは、まず**事実の書き漏れ**を疑う。
:::

## 次回への接続

この回では、答えが複数あるとき「次の解」を押して1つずつ出した。
`drinks(X, cocoa)` は2人、`ride_together(X, Y)` はもっと多くの組を返したはずである。

では、**Prolog はどうやって次の候補を見つけているのか。**
名簿の上から順に試しているのか、それとも別の順序があるのか。
条件を満たさなかったとき、何が起きているのか。

第02回では、その動き（**生成とテスト**と**バックトラック**）を見えるようにする。
そのうえで、いまは表として与えられていた名簿を、
**手掛かりだけから復元する**問題を解く。表は与えられない。
「hikaru は電車通学」「コーヒーを飲む人はテニス部」のような文が9個あるだけで、
そこから4人分の3属性をすべて言い当てる。

::: note
**自由課題に向けて**: 身の回りにある「関係」を1つ思い浮かべて、
事実として書けそうか考えてみる。時間割、部活の兼部、履修条件、乗り換え路線など。
うまく書けなくてよい。どこで詰まったかが、第11回の題材選びで使える材料になる。
:::
