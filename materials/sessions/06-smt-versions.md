## 今回解く問題

第05回では、パッケージを「入れる」か「入れない」かの2択で表した。
現実のパッケージには**版**がある。「`net` は入っているが版が古すぎて使えない」
ということが起きるので、入れるかどうかだけでは足りない。

この回で扱うのは、第05回と同じ5つのパッケージに、導入できる版を付けたものである。

| パッケージ | 役割 | 導入できる版 |
|---|---|---|
| `app` | アプリ本体 | 版1, 版2 |
| `gui` | 画面を描く部品 | 版1, 版2, 版3 |
| `net` | 通信をする部品 | 版1, 版2, 版3, 版4 |
| `db` | 新しいデータ保存の仕組み | 版1, 版2 |
| `legacy` | 古いデータ保存の仕組み | 版1 |

::: {.note}
架空の設定である。実在のソフトウェアの依存関係ではない。
**1つのパッケージについて、同時に入れる版は1つだけ**とする。
:::

条件は第05回の5つをそのまま引き継ぐ。版は問わない。

1. `app` は必ず入れる（**必須**）
2. `app` を入れるなら `gui` も入れる（**依存**）
3. `gui` を入れるなら `net` も入れる（**依存**）
4. `app` を入れるなら、`db` か `legacy` の少なくとも一方を入れる（**択一**）
5. `db` と `legacy` は同時には入れられない（**競合**）

そのうえで、版に関する条件を4つ足す。ここがこの回の新しいところである。

| 記号 | 条件 |
|---|---|
| (A) | `app` の**版2**を入れるなら、`gui` は**版2以上**でなければならない |
| (B) | `gui` を入れるなら、`net` は**版2以上**でなければならない |
| (C) | `gui` の**版3**を入れるなら、`net` は**版3以上**でなければならない |
| (D) | `legacy` を入れるなら、`net` は**版2以下**でなければならない |

問いは「この9つの条件をすべて満たす版の組合せはあるか。あるならどれか」である。

::: {.discuss}
(C) と (D) を並べて読んでみる。
**両方が同時に効く状況**を作れるだろうか。作れるとしたら、そのとき `net` は何版か。
:::

## 変数・定義域・制約・目的へ分解

第03回で決めた語彙を、今回の問題に当てる。

| 語 | この問題では |
|---|---|
| 変数 | 各パッケージについて「どの版を入れるか」 |
| 定義域 | `0` から、そのパッケージの最新版までの整数 |
| 制約 | 必須・依存・択一・競合の5つと、版の条件 (A)〜(D) |
| 目的 | なし（条件を満たすものが1つ見つかればよい） |

いちばん大事なのは**定義域の決め方**である。この回では次のように決める。

::: {.important}
- `0` は「そのパッケージを**入れない**」
- `1` 以上は「**その版を入れる**」

こう決めておくと、「入れる」は `!= 0`、「入れない」は `== 0` と書ける。
入れるかどうかと、どの版かを、**1つの変数で同時に表せる**。
:::

第05回では「入れるかどうか」だけを1つの真偽変数が持っていた。
今回はそこに「どの版か」を重ねている。値が2つ以上あるのだから、真偽では足りない。

## 理論概説

### SAT では表しにくいもの

第05回のやり方で版を表そうとすると、こう書くことになる。

- `net_1`（`net` の版1を入れる）
- `net_2`（`net` の版2を入れる）
- `net_3`、`net_4`

`net` は4つ、`gui` は3つ、というように**版の数だけ真偽変数が要る**。
5つのパッケージで合わせて12個になる。
さらに「同時に入れる版は1つだけ」を自分で書かなければならない。
これは第05回の「高々一つ」である。

```{.z3py filename="Boolean で書くと（比較のためだけのコード）"}
# net の4つの版から、同時に真になるのは高々一つ
for i in range(1, 5):
    for j in range(i + 1, 5):
        s.add(Or(Not(net[i]), Not(net[j])))
```

5つのパッケージ全部にこれを書くと、追加の節が11本になる。
そのうえで「`net` は版2以上」は次のように書く。

```{.z3py filename="「版2以上」を Boolean で書く"}
s.add(Or(net[2], net[3], net[4]))
```

版が10個あれば、この `Or` に9個並ぶ。書けるが、読みにくい。

### SMT: 論理の骨組みに背景理論を足す

::: {.term}
[**SMT**](../references/glossary.md#smt)（satisfiability modulo theories）とは、
命題論理の骨組みに[**背景理論**](../references/glossary.md#background_theory)を
組み合わせた充足可能性のことである。

背景理論とは、「整数の大小」「実数の四則」のような、
**値の世界ごとの決まりごと**を担当する部品だと考えればよい。
:::

背景理論に整数を選ぶと、`v_net >= 2` という式を**そのまま制約として書ける**。
`Or` を並べる必要はない。

ソルバーの中では、次のような分業が起きている。

```{.text filename="処理イメージ"}
  論理の骨組み            背景理論（整数）の担当
  ────────────            ──────────────────────
  (A ∨ B) ∧ ¬C     ←→     A: v_net ≥ 2
                          B: v_net = 0
                          C: v_net > 4
```

1. 骨組みだけを見て、$A$ を真、$B$ を偽、$C$ を偽、… と仮に決める。
2. その組み合わせが**整数の世界で成り立つか**を、背景理論の担当が調べる。
3. 成り立たなければ「その組み合わせは無理だ」と骨組み側へ伝え、骨組み側がやり直す。

この往復があるので、`>=` や `<=` を直接書ける。
詳しい図解は [SAT・SMT 概説](../references/logic-sat-smt.md)にある。

### `sat` / `unsat` / `unknown`

Z3 の `check()` が返す値は3つある。第05回では2つしか出てこなかった。

| 返り値 | 意味 |
|---|---|
| `sat` | 条件をすべて満たす割り当てが**ある**。`model()` で読める |
| `unsat` | どう値を選んでも同時には満たせない |
| [`unknown`](../references/glossary.md#unknown_result) | **確かめきれなかった** |

::: {.note}
`unknown` は「解が無い」という意味では**ない**。「有無を判定できなかった」である。
背景理論が難しいとき（実数どうしの掛け算や、「すべての〜について」を式の中に書いた場合など）や、
制限時間で打ち切られたときに返る。

**この科目で扱う範囲では `unknown` は出ない。**
整数の足し算と大小比較だけを使うかぎり、Z3 は必ず `sat` か `unsat` を返す。
それでも `check()` の分岐は `== sat` で書く。
`unsat` と `unknown` をまとめて「解は読めない」として扱えばよい。
:::

MiniZinc にも同じ区別がある。`=====UNKNOWN=====` がそれである
（[MiniZinc 実行環境の使い方](../references/setup-minizinc.md)の区切り記号の表）。

### どちらで書くかは設計の判断である

::: {.term}
[**符号化の選択**](../references/glossary.md#encoding_choice)とは、
同じ条件を真偽変数で書くか整数変数で書くかの判断のことである。
**どちらか一方が常に正しいわけではない。**
:::

目安は次のとおりである。

| 表したいもの | 型 | 例 |
|---|---|---|
| 入れるか入れないかの2択 | `Bool` | 第05回のパッケージの導入 |
| いくつかの選択肢から1つ。順序に意味が無い | `Bool` を選択肢の数だけ + 「ちょうど一つ」 | 地区の色（第05回の発展） |
| **大小や順序に意味がある**数 | `Int` | バージョン番号（この回） |

`Real`（実数）や `BitVec`（ビット列）もあるが、この科目では使わない。
選び方の目安は [SAT・SMT 概説](../references/logic-sat-smt.md)の「型の選び方」にある。

## 概念と構文

### 整数変数を作る

::: {.term}
[**整数変数**](../references/glossary.md#integer_variable)は、
大小の比較ができる値を取る決定変数である。Z3Py では `Int` で作る。
:::

```{.z3py filename="整数変数"}
n = Int("n")
a, b = Ints("a b")
```

::: {.warning}
**`Int` には範囲が付いていない。**
MiniZinc の `var 0..2` は宣言に定義域が書けたが、
Z3 の `Int` は宣言しただけでは**どんな整数にもなれる**（負の数にも）。
定義域は**制約として自分で書く**。

```{.z3py filename="定義域を書く"}
s.add(n >= 0, n <= 2)          # add は制約を複数まとめて受け取れる
```

書き忘れると、`v_net = 99` のような「存在しない版」が返ってくる。
:::

### 比較と、入れるかどうかの判定

比較演算子はそのまま制約になる。

| 書き方 | 意味 |
|---|---|
| `v == 0` | そのパッケージを入れない |
| `v != 0` | そのパッケージを入れる（版は問わない） |
| `v >= 2` | 版2以上を入れる |
| `v <= 2` | 版2以下（`0` すなわち「入れない」も含む） |
| `And(v >= 2, v <= 4)` | 版2以上4以下 |

::: {.warning}
`v <= 2` は `v == 0` も含む。
「入れる、かつ版は2以下」と言いたいなら `And(v != 0, v <= 2)` と書く。
**「入れない」を範囲の中に混ぜてしまう**のが、この回で最も多い誤りである。
:::

### 自然言語から整数の条件へ

第05回の対応表を、版のある世界へ書き直したものである。
**この対応表がこの回の中心**である。

| 日本語の条件 | 論理式 | Z3Py |
|---|---|---|
| A を必ず入れる（版は問わない） | $v_a \neq 0$ | `s.add(v["a"] != 0)` |
| A を入れるなら B も入れる | $v_a \neq 0 \to v_b \neq 0$ | `s.add(Implies(v["a"] != 0, v["b"] != 0))` |
| A を入れるなら B は版2以上 | $v_a \neq 0 \to v_b \geq 2$ | `s.add(Implies(v["a"] != 0, v["b"] >= 2))` |
| A の版2を入れるなら B は版2以上 | $v_a = 2 \to v_b \geq 2$ | `s.add(Implies(v["a"] == 2, v["b"] >= 2))` |
| A を入れるなら B か C の一方は入れる | $v_a \neq 0 \to (v_b \neq 0 \lor v_c \neq 0)$ | `s.add(Implies(v["a"] != 0, Or(v["b"] != 0, v["c"] != 0)))` |
| B と C は同時に入れられない | $v_b = 0 \lor v_c = 0$ | `s.add(Or(v["b"] == 0, v["c"] == 0))` |

::: {.term}
[**バージョン範囲**](../references/glossary.md#version_range)とは、
依存先が満たすべき版の区間のことである。
下限だけ（`>= 2`）、上限だけ（`<= 2`）、両方（`>= 2` かつ `<= 4`）の3つの形がある。
:::

**依存元を入れないときは、範囲の条件を効かせない。**
これが `Implies` の左側に `v_a != 0` を置く理由である。
「`app` を入れないのに `gui` の版が2以上でなければならない」というのは、
条件として言いすぎである。

### 値を読む

```{.z3py filename="整数の値を読む"}
if s.check() == sat:
    m = s.model()
    print(m[n].as_long())
```

::: {.warning}
`m[n]` は Z3 の値であって Python の `int` ではない。
`m[n] + 1` と書くと `3 + 1` という**式**が表示されるだけで、計算されない。
必ず `as_long()` を通してから計算する。
:::

使う API の一覧は [Z3Py 早見表](../references/z3py-cheatsheet.md)にある。
この回で新しく使うのは `Int` / `Ints` / 比較演算子 / `as_long` だけである。

## 小さな実行例

パッケージに入る前に、変数2つの小さな例で書き方を確かめる。
`a` は版1か版2、`b` は版1から版3まであるとする。

- `a` は必ず入れる
- `a` を入れるなら、`b` は版2以上でなければならない

```{.z3py filename="小さな例"}
from z3 import *

va, vb = Ints("va vb")

s = Solver()
s.add(va >= 0, va <= 2)              # a の定義域（0 は「入れない」）
s.add(vb >= 0, vb <= 3)              # b の定義域

s.add(va != 0)                       # a は必ず入れる
s.add(Implies(va != 0, vb >= 2))     # a を入れるなら b は版2以上

print(s.check())
m = s.model()
print("va =", m[va].as_long(), " vb =", m[vb].as_long())
```

```solver
sat
va = 1  vb = 2
```

`a` は版1、`b` は版2という組合せが返った。
`b` は版3でもよいので、これは**1つの例**であって唯一の答えではない。

::: {.note}
第05回と同じで、返ってくる割り当ては1つの例である。
「他にもあるか」は聞かないと分からない。
:::

## 予想してから試す

::: {.predict}
上の4つの条件に、5つ目として `vb <= 1`（`b` は版1以下）を足す。何が起きると思うか。

1. `va = 1`、`vb = 1` が出る
2. `va = 0`、`vb = 1` が出る（`a` を入れないことで逃げる）
3. `unsat` が出る
4. `unknown` が出る

選んだ理由も一緒に書き出してから実行する。
**`a` を入れないことが許されているかどうか**を確かめるとよい。
:::

```{.z3py filename="条件を1つ足す"}
s.add(vb <= 1)
print(s.check())
```

```solver
unsat
```

`va != 0` があるので、`a` を入れないという逃げ道は無い。
`a` を入れる以上、`vb >= 2` が要求される。
ところが `vb <= 1` と言われている。**どう値を選んでも両立しない。**

::: {.check}
ここまでで、次を確認しておく。

- `0` が「入れない」を表すという決めごとを、自分の言葉で説明できる
- `Int` に定義域が付いていないので、範囲を制約として書く必要があることを説明できる
- `v <= 2` が `v == 0` を含んでしまうことを説明できる
:::

## 必須演習

::: {.exercise level=required}
### 版のある5つのパッケージの基本モデルを書く

`workbook/sessions/06-smt-versions/versions.py` の
`# TODO(1)` から `# TODO(5)` までを埋め、
版の条件を除いた5つの条件（必須・依存・依存・択一・競合）を満たす
版の組合せを1つ求める。

**自分で決める1点**: `TODO(5)`（`db` と `legacy` は同時には入れられない）は、
次の2つのどちらで書いてもよい。**どちらか一方を選んで書く。**

```{.z3py}
s.add(Or(v["db"] == 0, v["legacy"] == 0))          # どちらかの版は 0
s.add(Not(And(v["db"] != 0, v["legacy"] != 0)))    # 両方に版が付くことはない
```

**完了条件**: 実行して `sat` と版の一覧が表示され、
その一覧が5つの条件をすべて満たしていることを、
**条件を1つずつ読み上げて**確かめられる。
さらに、表示された版がすべて「導入できる版」の範囲に入っている。
そのうえで、**なぜ「入れない」を版 `0` で表せるのか**を1行で書く
（`0` を「導入できる版」の中に入れなかったら何が起きるか）。

```console
$ python3 versions.py
```

埋める前に一度実行してみるとよい。
制約を1つも足していない状態では**全部「入れない」**が返る。
第05回と同じで、**制約を書いた分だけが守られる**ことの確認になる。
:::

::: {.hint summary="ヒント1: 定義域の書き方"}
`LATEST` は辞書で、`LATEST["net"]` が `4` になっている。
パッケージ名を順に取り出して、2つの制約を足す。

```{.z3py}
for name in PACKAGES:
    s.add(v[name] >= 0, v[name] <= ?)
```

`s.add` はカンマで区切って複数の制約を一度に受け取れる。
:::

::: {.hint summary="ヒント2: 「入れる」を条件に書く"}
第05回では `use["app"]` がそのまま「入れる」という命題だった。
今回は `v["app"]` が**整数**なので、そのまま制約にはできない。
「入れる」は「`0` ではない」に置き換える。

依存の `Implies` も、左右の両方をこの形に直す。
「`app` を入れるなら `gui` も入れる」は
「`v["app"]` が `0` でないなら、`v["gui"]` も `0` でない」である。
:::

::: {.hint summary="ヒント3: 択一と競合"}
「`db` か `legacy` の少なくとも一方を入れる」は、
`Or` の中に「入れる」を2つ並べる。

「同時には入れられない」は、
第05回では $\neg d \lor \neg l$ と書いた。
`Not(...)` の代わりに「入れない」（`== 0`）を使えば、そのまま同じ形になる。
:::

::: {.hint summary="ヒント4: 解答"}
```{.z3py filename="versions.py（TODO(1)〜TODO(5)）"}
# TODO(1) 定義域
for name in PACKAGES:
    s.add(v[name] >= 0, v[name] <= LATEST[name])

# TODO(2) app は必ず入れる
s.add(v["app"] != 0)

# TODO(3) 依存関係
s.add(Implies(v["app"] != 0, v["gui"] != 0))
s.add(Implies(v["gui"] != 0, v["net"] != 0))

# TODO(4) app を入れるなら db か legacy の少なくとも一方
s.add(Implies(v["app"] != 0, Or(v["db"] != 0, v["legacy"] != 0)))

# TODO(5) db と legacy は同時に入れられない
s.add(Or(v["db"] == 0, v["legacy"] == 0))
```

実行すると `sat` になり、`app` `gui` `net` と、
`db` か `legacy` のどちらか一方に版が付いた組合せが返る。
**どの版が返るかは決まっていない。**
この段階では版に関する条件を1つも書いていないので、
どの版でも条件を満たす。
:::

## 標準演習

::: {.exercise level=standard}
### バージョン範囲を足し、充足可能と充足不能を判定する

`versions.py` の「標準演習」の位置に、
「今回解く問題」の (A)〜(D) の4つの条件を足す。
そのあと、次の4つの構成をそれぞれ試す。

| 構成 | 足す条件 |
|---|---|
| 0 | （(A)〜(D) を足しただけ） |
| 1 | `app` は**版2**を入れる |
| 2 | `legacy` を入れる |
| 3 | `gui` は**版3**を入れる |
| 4 | `gui` は**版3**を入れる、**かつ** `legacy` を入れる |

**完了条件**: 次の表が埋まっていて、
構成4が `unsat` になる理由を**どの条件とどの条件が両立しないのか**を
名指しして説明できる。

| 構成 | `check()` の結果 | `net` の版 | 気づいたこと |
|---|---|---|---|
| 0 | | | |
| 1 | | | |
| 2 | | | |
| 3 | | | |
| 4 | | — | |

考えどころは3つある。

- 構成1で `gui` の版が変わったか。変わったなら、どの条件に押されたのか。
- 構成2と構成3では、`net` の版がそれぞれどちら向きに押されたか。
- 構成4で両立しなくなったのは、どの2つの条件か。
  片方を外すと `sat` に戻るかを確かめる。
:::

::: {.hint summary="ヒント1: (A)〜(D) の書き分け"}
4つの条件は、すべて「〜なら〜」の形である。
違うのは**左側の書き方**である。

- 「`app` の**版2**を入れるなら」は、版を名指ししている（`== 2`）
- 「`gui` を入れるなら」は、版を問わない（`!= 0`）

右側は「以上」（`>=`）か「以下」（`<=`）である。
上の「自然言語から整数の条件へ」の表の3行目と4行目を見比べる。
:::

::: {.hint summary="ヒント2: 構成を切り替えるには"}
条件を書いたり消したりを繰り返すと、
どれを足した状態なのかが分からなくなる。

構成ごとに `s.add(...)` の行を1行だけ足し、
試し終えたら `#` でコメントにして次へ進む、という進め方にすると混乱しにくい。
表の「気づいたこと」は、実行するたびにその場で書く。
:::

::: {.hint summary="ヒント3: unsat の理由を名指しする"}
「ソルバーがそう言ったから」で止めない。

構成4では `gui` の版が3に固定され、`legacy` が入る。
このとき (C) は `net` に**下限**を要求し、(D) は `net` に**上限**を要求する。
2つの範囲が重なっているかどうかを、数直線に書いてみる。

重なっていないと分かったら、(C) と (D) のどちらか一方を消して実行し、
`sat` に戻ることを確かめる。**戻ることまで確かめて初めて名指しできる。**
:::

## 発展演習

`Solver()` は「条件を満たすものを1つ」返す。
複数ある解のうち**いちばん良いもの**が欲しいときは `Optimize()` を使う。
たとえば「なるべく新しい版を選ぶ」は、版番号の合計を最大化すればよい。

```{.z3py filename="Optimize の入口"}
o = Optimize()                       # Solver() の代わりに使う
# ここへ制約を足す。書き方は Solver とまったく同じ（o.add(...)）
h = o.maximize(Sum([v[name] for name in PACKAGES]))
print(o.check(), o.upper(h))         # upper(h) が最大値
```

`o.model()` の読み方も `Solver` と同じである。
`minimize` にすれば最小化になる。

::: {.note}
**最適化の本番は第07回である。**
そちらでは MiniZinc に戻り、目的関数の設計そのものを扱う。
ここで覚えるのは「Z3 にも同じことができる入口がある」ということだけでよい。
:::

::: {.exercise level=advanced}
### いずれか1つを選ぶ

**A. 既存環境からの変更数を最小化する**

いま入っている版が次のとおりだとする。

| パッケージ | いまの版 |
|---|---|
| `app` | 版1 |
| `gui` | 版3 |
| `net` | 版1 |
| `db` | 入れない |
| `legacy` | 版1 |

この状態は (A)〜(D) を満たしていない。
条件を満たす状態へ移りたいが、**変える本数はできるだけ少なくしたい**。

`Optimize` を使って、版が変わるパッケージの本数を最小化する。
数え方は「変わっていれば 1、変わっていなければ 0」を足し合わせればよい。

```{.z3py filename="数え方"}
changes = Sum([If(v[name] != CURRENT[name], 1, 0) for name in PACKAGES])
```

確かめたいこと。

- 最小の変更数はいくつか。**1本では済まない**理由を条件で説明できるか。
- 同じ変更数の答えが**2通り以上ある**か。あるならどれか
  （`Optimize` は1つしか返さない。もう1つを出すには、
  返ってきた答えを除外する制約を足して解き直す。第04回の数独と同じやり方である）。

**B. 満たせない推奨依存の数を最小化する**

「守れたらうれしいが、守れなくても構わない」条件を**推奨依存**という。
次の3つを推奨依存とする。

1. `legacy` を入れる（古い形式のデータを読みたい）
2. `gui` は版3を入れる（新しい画面が使える）
3. `net` は版4を入れる（速い）

必須の条件（(A)〜(D) を含む）は必ず守ったうえで、
**満たせない推奨依存の本数を最小にする**。

```{.z3py filename="数え方"}
unmet = Sum([If(cond, 0, 1) for cond in RECOMMENDS])
```

確かめたいこと。

- 3つ全部は満たせるか。満たせないなら、どれとどれが両立しないか。
- 最小の未達本数はいくつか。そのときどの推奨をあきらめたか。
- 推奨依存とハード制約の違いを、モデルの書き方の違いとして説明できるか
  （[第09回](09-roster-soft.md)のソフト制約の前振りである）。
:::

## よくある誤り

| 症状 | 原因 | 直し方 |
|---|---|---|
| `v_net = 99` のような存在しない版が返る | 定義域の制約を書いていない | `s.add(v[name] <= LATEST[name])` を足す |
| 負の版が返る | 同上（下限を書き忘れた） | `s.add(v[name] >= 0)` を足す |
| 「入れない」はずのパッケージに版が付く | 「入れる」を `!= 0` ではなく `>= 0` と書いた | `>= 0` はすべての版で真になる。`!= 0` に直す |
| 「版2以下を入れる」のつもりが「入れない」が選ばれる | `v <= 2` に `v == 0` が含まれている | `And(v != 0, v <= 2)` と書く |
| `TypeError` や `AttributeError: 'NoneType'` が出る | `m[v[name]]` が `None` になっている | その変数を制約に一度も入れていない。定義域の制約を書けば必ず現れる |
| `m[n] + 1` が `3 + 1` と表示される | `as_long()` を通していない | `m[n].as_long() + 1` に直す |
| `Implies` の左側を書かず、範囲だけ足した | 依存元を入れないときにも範囲が効いてしまう | `Implies(v["a"] != 0, ...)` の形に戻す |
| `unsat` なのに `model()` を呼んだ | `if s.check():` と書いている | `if s.check() == sat:` に直す |

::: {.warning}
**`sat` が出たことは、モデルが正しいという意味ではない。**
条件を1つ書き忘れていても、ソルバーはその条件を無視した「答え」を平気で返す。
返ってきた版の組合せを、**元の日本語の条件と1つずつ突き合わせる**。
特に定義域は書き忘れやすい。表示された版が実在するかを毎回見る。
:::

## 扱わないこと

- **背景理論の網羅と、「すべての〜について」を式の中に書く書き方（量化子）** →
  背景理論は [SAT・SMT 概説](../references/logic-sat-smt.md)、量化子は番外の自習ページ
  [論理の入門(1)](../references/logic-intro.md#quantifiers)に名前だけ挙げた。
  この科目の到達点ではない。対象が有限なら量化子を `And` / `Or` の並びに展開できる、
  その理由は[論理の入門(2)](../references/logic-semantics.md#finite-expansion)にある
- **`Real` と `BitVec`** → 同上の「型の選び方」。
  この科目では `Bool` と `Int` だけを使う
- **`unsat_core`（矛盾の原因の抽出）と incremental solving** →
  扱わない。原因の切り分けは、条件を手で外して解き直す方法で行う
  （[Z3Py 早見表](../references/z3py-cheatsheet.md)の `push` / `pop`）
- **`Optimize` の本格的な解説** → 発展演習で入口だけ触れる。
  目的関数の設計は[第07回](07-theme-assignment.md)から MiniZinc で扱う
- **実在のパッケージ管理ソフトの依存解決** → この科目では扱わない。
  ここで作ったモデルは、考え方を体験するための単純化した設定である

## 次回への接続

この回で `Optimize` の入口を見た。
「条件を満たす答え」ではなく「**いちばん良い答え**」を探す、という話である。

第07回からは MiniZinc に戻り、最適化そのものを扱う。
題材は、何人かを定員付きの研究テーマへ割り当てる問題である。

目的関数であり、目的関数の作り方で「良い解」の意味が変わる。

::: {.note}
**自由課題に向けて**: 自分が考えている問題の変数は、
真偽で足りるか、それとも大小に意味がある数か。
数なら `Int` を選ぶ。ここまでの2回で、Z3 を選ぶ場合の主力パターンは出そろっている。
:::
