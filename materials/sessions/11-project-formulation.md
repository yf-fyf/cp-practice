# 第11回 自由課題: 問題選定と定式化

## この回の目標

この回を終えると、次のことができる。

- 解きたい問題を、授業期間内に扱える大きさへ絞り込める
- その問題を変数・定義域・ハード制約・ソフト制約・目的の語彙で書き出せる
- 入力データをどこから持ってくるかと、その扱いの制限を説明できる
- MiniZinc と Python+Z3 のどちらを主に使うかを、理由とともに選べる

## 今回やること

第10回までで [定式化の7手順](../references/modeling-steps.md)を一通り経験した。
第11回から第14回は、同じ7手順を**自分で選んだ問題**に対して回す。

この回で書くのは**企画書**である。モデルはまだ書かない。

| 時間 | 活動 |
|---|---|
| 15分 | 自由課題の進め方・成果物・評価の観点を確かめる（[自由課題の案内](../projects/README.md)） |
| 20分 | 題材を選ぶ。[テーマ例](../projects/README.md#テーマ例)から選ぶか、自分の問題を持ち込む |
| 30分 | 企画書の**最小版（3節）**を埋める（[企画書テンプレート](../projects/proposal-template.md#minimal-proposal)）。残りは次回までの宿題 |
| 20分 | 教員との個別レビュー。制約の曖昧さ・規模・ツール選択を調整する |
| 15分 | 直した企画書で、最小インスタンスの形を決める |

::: important
**この回で最も時間を使うべきなのは、問題を小さくすることである。**

思いついた問題は、たいてい授業期間には大きすぎる。
条件を減らし、対象を減らし、期間を短くして、
**手作業でも答えを確かめられる大きさ**まで落とす。
大きい版は、最小版が動いたあとで戻ってくればよい。
:::

### 問題の選び方

持ち込む問題は、次の3つを満たすものにする。

| 条件 | 見分け方 |
|---|---|
| **規模** | 最小の例が、紙の上で答えを確かめられる大きさになる（数独なら4×4、勤務表なら4人・3日の水準） |
| **データ** | 架空のデータを自分で作れる。実在のデータを使うなら、公開・改変してよいことを確認できる |
| **7手順で書ける** | 決定変数が何かを1文で言える。「良い解」の条件が言える。答えが正しいことを確かめる方法が言える |

3つ目が最も重要である。第10回の最後に書いた1行
——「返ってきた答えが正しいことを、どうやって確かめるか」——
がまだ書けないなら、その問題は**仕様が決まっていない**。
何を満たしていれば正解なのかが決まっていないということだからである。

::: warning
**実在の個人・団体のデータをそのまま使わない。**

勤務表・時間割・名簿の類は、身の回りの実物を使いたくなる題材である。
しかし成果物は提出し、発表で画面に映す。
氏名・所属・希望のような情報は、**架空のものに置き換えてから**使う。

公開されているデータセットを使う場合は、
出所と利用条件を企画書の「データの出所と権利」欄に書く。
:::

### ツールを選ぶ

主に使う道具を1つ決める。もう一方を**選ばない理由**も1〜2文で書く。
選択そのものより、理由を言葉にすることに意味がある。

問題の性質と道具の対応は
[企画書テンプレートの判断表](../projects/proposal-template.md#主ツールと選択理由)にある。

迷ったら、**第03〜10回で自分がよく読めたほうの回の道具**を選ぶ。
自由課題は道具に慣れる場ではなく、問題を解く場である。

::: note
どちらでも書ける問題は多い。グラフ彩色は Prolog・MiniZinc・SAT 符号化の
3通りで書ける（[グラフ彩色の複数表現](../references/graph-coloring.md)）。
「どちらでも書ける」と分かったうえで一方を選ぶのは、正当な選び方である。
:::

## 扱わないこと

- **実装** → 第12回。この回はモデルを書き始めない。
  書き始めると、書けるように問題のほうを歪めてしまう
- **入力規模の拡大** → 第13回。この回で決めるのは最小インスタンスだけである
- **発表資料** → 第14回
- **新しい構文・新しい道具** → この科目では扱わない。
  第01〜10回で出た範囲で書けるところまでを題材にする。
  早見表は [MiniZinc](../references/minizinc-cheatsheet.md) /
  [Z3Py](../references/z3py-cheatsheet.md)にある

## 次回への接続

第12回は、企画書の最小インスタンスを実際に動かす。

次回までに、**最小インスタンスの入力を数値まで書き下しておく**。
「4人・3日」ではなく、4人の名前と3日の必要人数を全部書く。
ここが決まっていないと、次回は数値を考える時間で終わる。
