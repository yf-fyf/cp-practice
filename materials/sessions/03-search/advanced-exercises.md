# 第03回の発展　推論と探索を確かめる

候補をまとめて考える推論、渡された盤面の検査、すべての解を探すプログラムを扱う。各問に必要な条件と出発点を示す。[第03回の本文](lesson.md)の必修は手で追う範囲であり、ここでの実装完成は次回の前提にしない。

## 候補集合をまとめた推論

一要素集合からしか削らない規則では、候補が二つずつ残る状態で止まることがある。互いに異なる値が必要なマスをまとめると、さらに何が分かるだろう。

::: {.given label="三変数の条件"}
各変数の候補集合Dは、その変数にまだ許している整数を表す。一要素集合なら、その整数に確定している。比較する基本の削減規則は、確定した変数の値を、同じ重複禁止に属する他の未確定変数の候補から取り除くものとする。

A・B・Cは互いに異なる整数とし、候補を $D_A=D_B=\{3,4\}$、$D_C=\{1,3,4\}$ とする。三つ以外の変数や、別の制約はない。

比較する別の問題では、X・Y・Zが互いに異なり、すべての候補が $\{1,2\}$ であるとする。
:::

1. 確定した値からだけ削る規則では、A・B・Cの候補を減らせない理由を説明する。
2. A・Bをまとめて考え、Cから除ける数字を求める。A・Bのどちらがどの値かを仮定せずに説明する。
3. X・Y・Zの問題は、候補が空でなくても解なしであることを説明する。

自己確認では、前半はC=1が必要、後半は解なしとなる。AとBは3・4を一つずつ使うので、Cがそれらを使う余地はない。三つの変数に二つしか異なる値を用意できない場合も、同じ数え方で考えられる。

::: {.hint summary="ヒントを開く：マスと値の個数"}
三つの椅子に、互いに異なる二つの番号だけを付けられるだろうか。候補を一つずつ仮定する方法とは別に、必要な値の個数と使える値の個数を比べよう。
:::

一般化するなら、同じ全相異なりに属するマスの一部をS、そこで使える候補の和集合をVとする。Vの要素数がSのマス数より小さければ矛盾する。同数ならSがVの数字を使い切るので、同じ全相異なりの残りのマスからVを除ける。

全相異なりと、すべてのペアの不等号は同じ完成代入を許す。ここで比べたのは、候補から何を推論する規則かという違いである。[全相異なりの公式の意味](https://docs.minizinc.dev/en/stable/lib-globals-alldifferent.html)と、ソルバーが用いる伝播の実装を区別しよう。

## 完成盤面の検査

ソルバーが返したという理由だけで正しいとせず、盤面の条件を独立に確かめる関数を作る。解を新しく探すのではなく、与えられた一つの盤面を判定する問題である。

::: {.given label="入出力と条件"}
入力は `given` と `grid` の二つのリスト。行を上から順に、各行を左から右へ並べる。`given` は0〜4の整数16個で、0は空欄である。`grid` は検査対象であり、誤った範囲・長さ・値を含む可能性がある。

`grid` が整数16個で全値1〜4、0以外の初期値を保持し、各行・各列・四つの2×2ブロックの値が互いに異なれば `True`{.python}、一つでも違反すれば `False`{.python} を返す。ブロックは行1〜2／3〜4と列1〜2／3〜4で区切る。
:::

[check-start.py](../../../workbook/sessions/03-search/check-start.py)の `is_solution(given, grid)`{.python} を完成させる。作業1では長さ・整数型・値の範囲と初期値の保持、作業2では行・列・ブロックを検査する。JSONの読込みと、givenの入力形式の確認、判定結果の出力は配布済みである。

Pythonの添字は0から始まり、授業のr行c列は `4*(r-1)+(c-1)`{.python} 番目になる。例えば2行3列は添字6である。値を一行ずつ取り出した集合の要素数を調べれば、重複があるかを確認できる。

```sh
python3 check-start.py V1.json
```

この実行の期待結果はJSONの `true` である。次の七入力も実行し、正しい二盤面と、条件ごとに壊した盤面を区別しよう。出力は `true` または `false` の一語でよい。

| 入力 | 検査する例 | 期待結果 |
|---|---|---|
| [V1](../../../workbook/sessions/03-search/V1.json) | 初期値を保つ正しい完成盤面 | `true` |
| [V2](../../../workbook/sessions/03-search/V2.json) | 空盤面からの別の正しい解 | `true` |
| [V3](../../../workbook/sessions/03-search/V3.json) | 行の重複だけを含む | `false` |

長さ・型・範囲を先に調べれば、その後で16マスの添字を安全に使える。行が正しくても、列やブロックは別に確認する。初期値の0は比較から外すが、完成盤面の0は許さない。
:::

一つの拒否例だけで、すべての条件が正しく実装できたとは限らない。長さの違うリストや、一つの数字を文字列に変えた入力も作り、`False`{.python} を返すことを確かめよう。

## 伝播と全解探索

一つの解を見つけて止めず、基本4×4数独の解をすべて返す探索を実装する。完成した伝播規則を提供するので、発展1や発展2のプログラムを完成させている必要はない。

::: {.given label="探索する問題"}
各マスは1〜4、入力の0は空欄、0以外の初期値は保持する。各行・各列と、行1〜2／3〜4・列1〜2／3〜4で区切る四つの2×2ブロックを、それぞれ全相異なりとする。追加条件はない。

各候補集合は、そのマスにまだ許している数字の集合である。初期値のあるマスはその値だけの集合、空欄は{1,2,3,4}から始める。行は上から、列は左から読む。

`search(domains)`{.python} の入力は16個の候補集合のリスト、返り値は全完成盤面のリストとする。各盤面は整数16個のリストで、順序は上から各行を左から右へ。解なしは `[]`{.python}、同じ盤面を重複して返すことは禁止する。
:::

[search-start.py](../../../workbook/sessions/03-search/search-start.py)と[propagation.py](../../../workbook/sessions/03-search/propagation.py)を同じフォルダーに置く。入力は[branch.json](../../../workbook/sessions/03-search/branch.json)から始める。JSONの `given` は上から各行を左から右へ並べた16整数で、この入力の行ごとの値は `0021 / 0000 / 0010 / 2100`（`/` は改行）である。

提供する伝播は、各巡の開始時に確定した値を、同じ行・列・ブロックの別の未確定マスから一斉に除く。新しい確定値は次の巡から使い、変化が止まるか矛盾するまで繰り返す。`initial` が初期候補を作り、`propagate` が初期表を含む履歴を返す。最後の表は `propagate(domains)[-1]`{.python} で得られる。

`status` は空集合と確定値同士の衝突を調べ、`contradiction`（矛盾）・`complete`（全マス確定で衝突なし）・`stalled`（未確定のまま停止）を返す。探索では必ず伝播した後で使う。提供された初期候補から削減と仮定だけを行えば、初期値と1〜4の範囲は保たれる。完成時の判定には発展2の関数を使ってもよいが、必須ではない。

### 伝播と分岐の組合せ

作業1では伝播後の矛盾・完成・未確定を分け、作業2で未確定マスの全候補を場合分けする。最初は、左上から順に見つかる未確定マスを選べばよい。

1. 伝播して矛盾なら、その枝の解として空リストを返す。
2. 完成なら、各一要素集合から値を取り出し、一盤面だけ入ったリストを返す。
3. 未確定なら一マスを選び、候補を小さい順に一つずつ仮定する。
4. 各枝には独立した候補表を渡して再帰呼出しし、すべての枝の解を集める。

```sh
python3 search-start.py branch.json
```

期待するのは四つの完成盤面が入ったJSON配列である。一つ見つけた時点で `return`{.python} すると、別の枝の解を落とす。`status` が `stalled` の表を、そのまま完成盤面に変えて返してもいけない。

::: {.hint summary="ヒントを開く：枝ごとのコピー"}
`branch = domains`{.python} はコピーではない。外側のリストだけをコピーしても、中の集合を共有することがある。`[set(d) for d in domains]`{.python} で各集合も独立させ、そのコピーの一マスだけを仮定の一要素集合にする。
:::

### 全解と正しさの確認

動いたら、解なし・一解・複数解・空盤面を調べる。件数だけでは重複や取りこぼしを区別できないため、[確認用の全解データ](../../../workbook/sessions/03-search/solutions.json)と集合として比較する。

| 入力 | 期待する全解数 |
|---|---:|
| [demo.json](../../../workbook/sessions/03-search/demo.json)：`1004 / 0402 / 2040 / 0301` | 1 |
| [practice.json](../../../workbook/sessions/03-search/practice.json)：`4300 / 2003 / 0010 / 0004` | 1 |
| [branch.json](../../../workbook/sessions/03-search/branch.json) | 4 |
| [empty.json](../../../workbook/sessions/03-search/empty.json)：`0000 / 0000 / 0000 / 0000` | 288 |
| [conflict.json](../../../workbook/sessions/03-search/conflict.json)：`1010 / 0000 / 0000 / 0000` | 0 |

[compare-solutions.py](../../../workbook/sessions/03-search/compare-solutions.py)は、期待する盤面の集合と、出力の重複を確かめる確認用コードである。例えば空盤面の出力をファイルへ保存し、次のように照合できる。

```sh
python3 search-start.py empty.json > answers.json
python3 compare-solutions.py empty answers.json
```

全入力が通ったら、正しい解を削除しない理由、候補をすべて試せば解を漏らさない理由、再帰が有限回で終わる理由を説明する。未確定マスを選んで一要素へ制限するたび、未確定マスの数が減ることが、停止を考える手掛かりになる。

### 探索方針の比較

未確定マスのうち候補数が最も少ないものを選ぶ方法も実装する。同数なら左上からの順、値は小さい順に揃える。伝播規則は変えず、探索関数の呼出し数で仕事量を比較しよう。

呼出し数には、最初の根、矛盾した葉、完成した葉も含める。上の五入力では両方式が同じ回数になるが、[compare.json](../../../workbook/sessions/03-search/compare.json)の初期配置 `1000 / 0012 / 0000 / 0000` では差が出る。どちらも12解で、参照実装の呼出し数は左上優先26回、最少候補優先23回となる。

結果の集合が同じことを先に確かめ、他の初期配置でも比較する。候補数が少ないマスを選べば常に速くなる、と一例から結論しない。さらに候補集合をまとめる規則を加える場合は、マスの選択だけを変える実験と分ける。伝播自体にも計算が必要なので、呼出し回数と実行時間も別の指標である。
