# 自由課題の案内

第11回から第14回の4回は、**自分で選んだ問題**を制約プログラミングで解く。
第15回でその成果を発表する。

このページは自由課題全体の入口である。
各回で何をするかは、それぞれの回のページにある。

## 何をするのか

第01回から第10回までで、問題を解くための道具（Prolog・MiniZinc・Z3）と、
問題を分解する順序（[定式化の7手順](../references/modeling-steps.md)）を扱った。
自由課題は、その7手順を**題材が与えられていない状態で**回す。

与えられないのは題材だけである。手順は同じである。

| 手順 | 自由課題ではどこで行うか |
|---|---|
| 対象と入力データ | 第11回（企画書） |
| 決定変数 | 第11回（企画書）→ 第12回（実装） |
| 定義域 | 第11回（企画書）→ 第12回（実装） |
| ハード制約 | 第11回（一覧）→ 第12〜13回（実装） |
| ソフト制約 | 第11回（一覧）→ 第13回（実装） |
| 目的 | 第11回（一覧）→ 第13回（実装） |
| 検証 | 第13回（検証）→ 第14回（実験） |

## 4回の流れ

| 回 | やること | この回の終わりに欲しいもの |
|---|---|---|
| [第11回](../sessions/11-project-formulation.md) | 問題を選び、定式化する | 企画書 |
| [第12回](../sessions/12-project-minimal-model.md) | 最小インスタンスを動かす | 動くモデルと暫定 README |
| [第13回](../sessions/13-project-extension.md) | 制約・目的を足し、検証する | 標準規模の結果と検証記録 |
| [第14回](../sessions/14-project-completion.md) | 実験し、成果物を仕上げる | 成果物一式と発表資料の初版 |
| [第15回](../sessions/15-presentation.md) | 発表する | 提出と発表 |

::: important
**4回すべてを授業時間内で終えることは想定していない。**

各回の終わりに欲しいものは、次の回を始めるための前提である。
授業時間内に届かなければ、自習で続けてから次の回に来る。
特に第12回の「動くモデル」は、次の回で足す先が無くなるので落とせない。
:::

## 使う道具

MiniZinc と Python+Z3 のどちらを使ってもよい。第11回で選び、企画書に理由を書く。

- MiniZinc は [Playground](https://play.minizinc.dev/) をそのまま使う
  （[使い方](../references/setup-minizinc.md)）。
  手元で動かしたい場合の案内も同じページにある
- Python+Z3 は第05〜06回で入れた環境をそのまま使う
  （[使い方](../references/setup-z3.md)）。版は固定してある

Prolog は第01〜02回で完結しているので、自由課題の主ツールにはしない。
探索の様子を見せるための補助として使うのは自由である。

## 成果物

第15回に提出するものは次のとおりである。
提出前の確認には [成果物チェックリスト](deliverables-checklist.md)を使う。

| 成果物 | 中身 |
|---|---|
| 企画書 | 問題の背景と自然言語による仕様。変数・定義域・ハード制約・ソフト制約・目的の一覧 |
| モデルまたはプログラム | MiniZinc モデル、または Python+Z3 のプログラム |
| 入力データ | 1つ以上。最小インスタンスと標準規模の両方があるとよい |
| README | 実行環境と版・実行手順・データ・検証方法・既知の限界 |
| 検証記録 | 解が制約を満たすことを確かめた記録。正常例と反例 |
| 実験結果 | 複数条件または複数規模での実行結果の表 |
| 発表資料 | 第15回で使うもの |

記入用のテンプレート一式は `workbook/projects/` に入っている
（入手は [演習ファイルの使い方](../../workbook/README.md)）。
自分の作業用ディレクトリへ複製して使う。

## 評価の観点

**成果物の提出と成果発表が必須要件**である。
そのうえで、次の5つの観点で見る。

| 観点 | 見るところ |
|---|---|
| **定式化の妥当性** | 問題を変数・定義域・制約・目的へ分解できているか。規模の絞り方が適切か |
| **モデルの正しさと検証** | 得られた解が制約を満たすことを、独立した方法で確かめているか |
| **規模と実験** | 複数の条件または規模で実験し、結果を根拠として示しているか |
| **成果物の再現性** | 第三者が README のとおりに実行して同じ結果を得られるか |
| **発表** | 問題設定から結果までを、コードを読んでいない人に一貫して説明できているか |

::: important
**動くコードを書いたかどうかだけを見るのではない。**

書いたものが正しいと言える根拠を持っているかを見る。
うまくいかなかった実験や、解けなかった規模を報告することは減点ではない。
**それを隠して「動きました」と述べることのほうが問題である。**
:::

観点ごとの詳しい段階は、授業内で示す。

## テーマ例

次は候補の一覧である。この中から選んでもよいし、自分の問題を持ち込んでもよい。

**難易度の目安**を印で示す。迷ったら ◎ から選ぶ。
◎ を選んだからといって評価が下がることはない。
評価の観点は「定式化・検証・実験・再現性・発表」であって、題材の派手さではない。

| 印 | 意味 |
|---|---|
| ◎ | **入門向け。まずここから。** 最小インスタンスが即決まり、決める変数が1種類で済む |
| ○ | 標準。決める変数が1〜2種類。制約が5本前後になる |
| △ | 発展。決める変数が2種類以上、または規模を落としにくい。時間に余裕がある人向け |

| 印 | テーマ | 決めること | 向いている道具 |
|---|---|---|---|
| ◎ | 座席割当 | 誰をどの席に座らせるか（隣り合わせたくない組がある） | MiniZinc |
| ◎ | 当番表（4人 × 3日） | どの日の当番を誰にするか（連日を避ける・不都合な日を外す） | MiniZinc |
| ◎ | 4×4 数独の**問題生成** | 一意解を持つ 4×4 盤面を作る（第04回の一意性の逆向き） | MiniZinc |
| ○ | メニュー・商品の組合せ選択 | 予算と条件を満たす組合せ | どちらでも |
| ○ | 周波数・通信チャネルの割当 | 各局に割り当てるチャネル（彩色問題の親戚） | どちらでも |
| ○ | 避難者グループと施設の割当 | どのグループをどの施設へ | MiniZinc |
| ○ | スポーツ大会の日程編成 | 対戦の組合せと日程 | MiniZinc |
| ○ | ソフトウェア依存関係解決の発展 | 導入するパッケージと版（第05〜06回の発展） | Python+Z3 |
| ○ | 魔方陣の生成 | 各マスの数 | MiniZinc |
| △ | 試験時間割と教室割当 | 科目 × 時間帯 × 教室の割当て（決める値が2種類） | MiniZinc |
| △ | 9×9 数独の問題生成 | 一意解を持つ 9×9 盤面を作る | MiniZinc |
| △ | ジョブショップスケジューリング | 各作業の開始時刻と使う機械（時刻が整数変数になる） | MiniZinc |
| △ | 魔方立方体の生成 | 各マスの数（3次元になる） | MiniZinc |
| △ | 論理回路の生成 | 与えた真理値表を満たす回路の構成 | Python+Z3 |

::: {.note}
**△ を選びたい場合は、まず ◎ の規模で1つ動かしてから広げる。**
たとえば試験時間割なら、先に「教室を1つに固定して時間帯だけ決める」形で動かす。
これは第12回から第13回への進み方（最小モデル → 制約追加）そのものである。
:::

授業で扱った勤務表を拡張してもよい。
ただしその場合は、**入力規模を増やすだけにしない**。
新しい制約・新しい目的・新しい検証方法のいずれかを足す。

::: note
**持ち込む問題の選び方**は [第11回](../sessions/11-project-formulation.md)にある。
規模・データの権利・7手順で書けるか、の3点で見る。
:::

## よくある質問

::: {.discuss}
**Q. 授業で扱っていない書き方を使ってもよいか。**

よい。ただし、自由課題は道具に慣れる場ではなく問題を解く場である。
新しい構文を調べる時間が、問題を考える時間を食っていないかを見る。
早見表（[MiniZinc](../references/minizinc-cheatsheet.md) /
[Z3Py](../references/z3py-cheatsheet.md)）の範囲で書けるなら、その範囲で書くほうがよい。
:::

::: {.discuss}
**Q. 標準規模で解が出ない（時間内に終わらない）。それでも提出してよいか。**

よい。**解けなかったことを結果として報告する。**
どこまでの規模なら解けたか、どこから終わらなくなったかを表にする。
第10回で扱ったとおり、正しさと速さは別に評価する。
:::

::: {.discuss}
**Q. 途中で題材を変えてもよいか。**

第12回までなら変えてよい。企画書も書き直す。
第13回以降の変更は、実験する時間が無くなるので勧めない。
題材を変えずに**規模を落とす**ほうを先に検討する。
:::

::: {.discuss}
**Q. 他の人と同じ題材を選んでもよいか。**

よい。同じ題材でも、決める変数と入れる制約は人によって変わる。
第15回でその差を見比べられるので、むしろ面白い。
ただし**モデルは各自で書く**。
:::

::: {.discuss}
**Q. 実在のデータを使ってもよいか。**

出所と利用条件を確認できるなら使ってよい。企画書にその欄がある。
確認できないもの、個人が特定できるものは使わない。
迷ったら架空のデータを自分で作る。
授業で使った勤務表・テーマ割当のデータも、すべて架空である。
:::

::: {.discuss}
**Q. 成果物はネットで公開されるのか。**

されない。教材サイトに載せることはしない。
:::
