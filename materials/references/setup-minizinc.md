# MiniZinc 実行環境の使い方

第03〜04回と第07〜10回で使う MiniZinc は、**ブラウザで開くだけ**で動く。
インストールもアカウント登録も要らない。

::: important
[**MiniZinc Playground を開く →**](https://play.minizinc.dev/)
:::

Playground は MiniZinc 本体を WebAssembly に変換したものである。
モデルの求解はブラウザの中で行われ、書いたモデルが外部のサーバへ送られることはない。

::: warning
Playground は外部のサービスである。画面の細部や名称は予告なく変わることがある。
このページに書いてあるボタン名が見つからないときは、
**同じ働きのボタンを探す**（「実行」＝三角の再生アイコン、など）。
:::

## 画面の見かた

画面は大きく3つに分かれている。

| 部分 | 何をするところ |
|---|---|
| ツールバー（上） | 実行、ソルバーの選択、ファイルの追加、共有リンクの作成 |
| エディタ（左・中央） | モデル（`.mzn`）やデータ（`.dzn`）を書く。ファイルごとにタブが並ぶ |
| 出力欄（右・下） | 解、統計、エラーが出る |

ツールバーで使うのは次の3つだけである。

| 操作 | 働き |
|---|---|
| 実行（再生アイコン） | いま開いているモデルをコンパイルして解かせる |
| ソルバーの選択（実行の隣） | 使うソルバーを選ぶ。既定は Gecode で、この科目では変えなくてよい |
| 共有（右上） | いまの内容を開くリンクを作る。提出や質問のときに使える |

## 基本の手順

1. エディタにモデルを書く（演習ファイルの `.mzn` を開いて貼り付ける）。
2. 実行を押す。
3. 出力欄に解が出る。エラーが出たら行番号を見てエディタに戻る。

たとえば次のモデルを貼って実行する。架空の3人に、重複しない番号を割り当てる。

```{.minizinc filename="hello.mzn"}
include "globals.mzn";

set of int: PEOPLE = 1..3;

array[PEOPLE] of var 1..3: seat;

constraint all_different(seat);
constraint seat[1] != 1;

solve satisfy;

output [ "seat = ", show(seat), "\n" ];
```

出力欄には次のように出る。

```solver
seat = [2, 3, 1]
----------
```

条件を満たす並べ方は他にもある。**どれが返るかはソルバー次第である。**
この教材に載せてある MiniZinc の出力は、
すべて既定のソルバー（Gecode）で実行したものである。

## 解の区切り記号を読む

MiniZinc の出力には決まった区切り記号が現れる。**エラーメッセージではない**。

| 出力 | 意味 |
|---|---|
| `----------` | 解を1つ出し終えた区切り |
| `==========` | 探索が終わった（もう解が無い、または最適だと確かめた） |
| `=====UNSATISFIABLE=====` | すべての制約を同時に満たす割当てが存在しない |
| `=====UNKNOWN=====` | 制限時間などで打ち切られ、有無が分からなかった |

`=====UNSATISFIABLE=====` はモデルが壊れているとは限らない。
「その条件では解けない」という**答え**である。
条件を1つずつ外して、どれが効きすぎているかを確かめる
（[よくあるエラーと対処](errors.md)）。

## データファイル（`.dzn`）を使う

第04回以降は、モデル（`.mzn`）と入力データ（`.dzn`）を分ける。
Playground ではファイルを追加してタブを増やし、実行時にデータファイルを選ぶ。

### 手順カード（モデル + データ）{#playground-card}

**第04回以降の演習は、どの回もこの5行で実行できる。**
演習ファイルの README はこのカードを指しているので、手順はここだけを見ればよい。

1. [MiniZinc Playground](https://play.minizinc.dev/) を開く（導入も登録も要らない）。
2. その回の `.mzn` の中身をエディタへ貼る。
3. ファイルを追加してタブを増やし、その回の `.dzn` の中身を貼る。
4. 実行する。データファイルを聞かれたら、使う `.dzn` にチェックを入れる。
5. データの追加や選択が画面上で見つからないときは、
   `.dzn` の中身を**モデルの末尾に貼り足す**（もう一方の `.dzn` の分は消しておく）。

5 の逃げ道があるので、Playground の画面が変わっても演習は止まらない。

ファイルを追加して `puzzle01.dzn` のような名前を付け、データを書く。

```{.dzn filename="puzzle01.dzn"}
n = 4;
```

そのあとモデルのタブに戻って実行する。データファイルを使うかどうかを尋ねられたら、
使うファイルにチェックを入れる。

::: note
モデル側で `int: n;` と**値を書かずに宣言**しておくと、`.dzn` 側の `n = 4;` が
その値になる。モデルに `int: n = 4;` と書いてしまうと、`.dzn` で上書きできない。
:::

## 複数の解を見る

`solve satisfy;` は解を1つ返して止まる。
別の解があるかどうかを見たいときは、ソルバーの設定で
「すべての解を出す」または「出す解の個数」を指定する。
第04回では**2つ目の解があるかどうか**だけを見る。全部を数え上げるのが目的ではない。

::: warning
この設定の名前と置き場所も、Playground の画面によって変わる。
見つからないときは、**モデルの側だけで同じことができる**。
見つかった解をデータとして受け取り、「それとは違う解」を要求する制約を1つ足す。

```{.minizinc filename="見つかった解を除外する"}
array[ROWS, COLS] of int: found;

constraint exists(r in ROWS, c in COLS)( x[r, c] != found[r, c] );
```

もう一度実行して `=====UNSATISFIABLE=====` が出れば、解は1つだけである。
やり方は第04回の教材ページにある。
:::

## 実行にかかった時間と規模を見る

[第10回](../sessions/10-roster-verification.md)では、入力の規模と実行時間の関係を記録する。
道具立てを増やさなくても、出力欄から次の3つが読める。

| 見るもの | 読み取れること |
|---|---|
| `----------` の本数 | 途中経過の解が何本出たか。最適化では改善のたびに1本増える |
| `==========` が出たか | **最適だと確かめられたか**。出なければ「まだ良い解があるかもしれない」 |
| 実行を押してから止まるまでの時間 | かかった時間。手元の時計でよい |

ソルバーの統計（探索した場合分けの数など）を表示する設定があれば、
それも比較の目安に使える。**無くても困らない。**

::: warning
**止まらないことがある。** 最適だと**証明する**のに時間がかかる問題では、
途中経過の解は次々出るのに `==========` がいつまでも出ない。

異常ではない。時間を決めて実行を止め、
**そこまでに出た最後の解**を使う。その解は制約をすべて満たしている。
ただし「これより良い解が無い」とは言えていない。
:::

## 書いたものを残す

Playground の内容は**そのブラウザの中にしか残らない**。
プライベートウィンドウ、履歴の消去、別の端末では引き継がれない。

::: important
**残したい内容は演習ファイル（`workbook/sessions/`）へコピーして保存する。**
ブラウザ任せにしない。共有リンクも、元の内容が消えれば意味が無くなる。
:::

## 日本語入力の注意

MiniZinc の記号はすべて半角である。日本語入力のまま書くと構文エラーになる。

| よくある取り違え | 正しい書き方 |
|---|---|
| 全角の `（` `）` `［` `］` | 半角の `(` `)` `[` `]` |
| 全角の `，` `；` | 半角の `,` `;` |
| 全角スペース | 半角スペース |
| 全角の `．．` | 半角の `..`（範囲） |

コメント（`%` から行末まで）と文字列の中には日本語をそのまま書いてよい。
`output` に日本語を混ぜても解の中身は変わらない。

## ローカルに MiniZinc を入れる（自由課題で選ぶ人向け）

第03〜10回はすべて Playground で足りる。**授業でローカル導入は行わない。**
自由課題（第11〜14回）で大きなモデルを扱いたい場合だけ、
公式の MiniZinc IDE バンドルを入れるとよい。IDE には Gecode・Chuffed などの
ソルバーが同梱されているので、別途ソルバーを入れる必要はない。

| OS | 入れ方の要点 |
|---|---|
| Windows | 公式サイトのインストーラを実行する。コマンドラインから使うなら `PATH` に導入先を足す |
| macOS | 配布されているディスクイメージを開き、アプリケーションフォルダへドラッグする |
| Linux | Snap（`snap install minizinc --classic`）または AppImage が手軽である |

導入元と最新の手順は[公式のインストール手順](https://docs.minizinc.dev/en/stable/installation.html)を見る。
入ったかどうかは版の表示で確かめる。

```console
$ minizinc --version
```

::: note
自由課題で MiniZinc を使うときは、**使った版と実行手順を成果物の README に書く**。
採点する側が同じ結果を再現できることが条件である。
:::

## 扱わないこと

- **探索アノテーション・ソルバーの切り替えによる高速化** → この科目では扱わない。
  「どう探すか」をソルバーに任せることが、この書き方の要点である
- **`output` の凝った整形** → [MiniZinc 早見表](minizinc-cheatsheet.md)に最小限だけ載せた
- **MiniZinc の全構文** → [公式ドキュメント](https://docs.minizinc.dev/)を見る
- **コマンドラインからの実行** → 自由課題でローカル導入を選んだ場合のみ、上記の版表示を入口にする
