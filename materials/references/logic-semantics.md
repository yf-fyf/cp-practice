# 論理の入門(2) 述語論理の意味論

[論理の入門(1) 読み方](logic-intro.md)では、「すべて」と「ある」を**読み分ける**ところまでを扱った。
このページはその続きで、**「真である」とはどういうことか**を定義の側から見る。
「すべての日について、ある資格者が夜勤にいる」が真か偽かは勤務表が決まってはじめて決まる。
その仕組みを書き下したものが**意味論**であり、ソルバーが探しているものの正体でもある。

::: note
このページは**番外の自習用**である。授業では扱わない。
ここに書いてあることの習得は必須の到達点ではない。
**先に[論理の入門(1)](logic-intro.md)を読むこと。**あちらが読み方、こちらが定義である。

番外(1)とは違い、このページでは記号（$\forall$ $\exists$ $\land$ $\lor$ $\neg$ $\to$ $\models$）を使うが、
定義には必ず日本語の言い換えを併記するので、記号を覚えていなくても読める。
読むのにかかるのは60〜90分である（評価表2つを手で追うなら、これくらいはかかる）。
:::

**このページの記号**を先に並べておく。読みだけ知っておけば足り、意味は初出の節で定義する。

| 記号 | 読み | 初出 |
|---|---|---|
| $\forall x\, \varphi$ / $\exists x\, \varphi$ | すべての $x$ について $\varphi$ / ある $x$ が存在して $\varphi$ | [何が論理式か](#syntax)。番外(1)の $\forall X.\ P(X)$ / $\exists X.\ P(X)$ と同じものである |
| $\varphi$ / $\psi$ | ファイ / プサイ。「論理式1つ」を指す文字 | [何が論理式か](#syntax) |
| $M$ / $D$ | 構造 / 領域 | [構造](#structure) |
| $P^{M}$ | 「$P$ の $M$ での解釈」 | [構造](#structure) |
| $\in$ / $\notin$ | 「〜の要素である」/「〜の要素でない」 | [構造](#structure) |
| $s$ / $s(x)$ | 付値 / 「$s$ が変数 $x$ に対応させた要素」 | [付値と充足](#satisfaction) |
| $M, s \models \varphi$ | 「$M$ と $s$ のもとで $\varphi$ を充足する」 | [充足関係の定義](#definition) |
| $\Gamma$ | ガンマ。文の集合を指す文字 | [モデル、充足可能、充足不能](#models) |
| $\varphi[x := e]$ / $\equiv$ | 「$x$ のところに $e$ の名前を書き入れた式」/「同じ真偽になる」 | [有限領域なら量化子は展開できる](#finite-expansion) |

## 命題論理の意味論を思い出す {#propositional-semantics}

第05回で扱った命題論理では、式が真になる仕組みはすでに定義してある。
命題変数それぞれに真か偽かを1つ決め（この決め方を**真理値割当て**という。
第05回では単に「割り当て」と呼んだ）、
$\neg$ $\land$ $\lor$ $\to$ の真理値表に従えば、式全体の真偽が**一意に決まる**。
すべての式を同時に真にする割当てが1つでもあれば**充足可能**であった。
真理値表そのものは[第05回](../sessions/05-sat-dependencies.md)の「理論概説」と
[SAT・SMT 概説](logic-sat-smt.md)にある。ここでは再掲しない。
述語論理でもこの形は変わらない。変わるのは**最初の「割当てを1つ決める」の中身**である。
Prolog の書き方で言えば、`drinks(X, cocoa)` には「真か偽か」を直接書き入れる場所が無く、代わりに
**どんな対象があって、どの述語がどの対象の組で成り立つか**（[構造](#structure)）と
**変数がどの対象を指すか**（[付値](#satisfaction)）の2つを決める。
この2つを決めれば式の真偽が一意に決まる、というのがこのページの中身である。

## 何が論理式か {#syntax}

::: {.term}
式を書くのに使う記号の一覧を**語彙**という。このページで使うのは次の3種類である。

- **述語記号**: `drinks` `club` `night` など。**引数の個数**が決まっている（`drinks/2` の `/2`）
- **定数記号**: `aoi` `cocoa` など。対象を1つ名指しする名前
- **変数**: $x$ $y$ など。何を指すかがまだ決まっていない名前

述語の引数に書けるものを**項**という。このページでは関数記号を扱わないので（下の important）、
項は**定数記号か変数の2つだけ**である。

述語記号 $P$ と項 $t_1, \dots, t_n$（$n$ は $P$ の引数の個数）を並べた $P(t_1, \dots, t_n)$ を
**原子式**という。これ以上分けられない、いちばん小さい式である。
**論理式**は次の作り方だけで作られる（$\varphi$・$\psi$ は「論理式1つ」を指す文字である）。

1. 原子式は論理式である
2. $\varphi$ が論理式なら $\neg \varphi$ も論理式である
3. $\varphi$ と $\psi$ が論理式なら $\varphi \land \psi$、$\varphi \lor \psi$、$\varphi \to \psi$ も論理式である
4. $\varphi$ が論理式で $x$ が変数なら $\forall x\, \varphi$ と $\exists x\, \varphi$ も論理式である
:::

::: important
**このページでは関数記号を扱わない。**だから上のとおり項は**定数記号か変数の2つだけ**で、
`f(x)` や `x + 1` のような書き方は出てこない。
**等号 $=$ も扱わない**（`x = y` は書けないものとして読む）。どちらも入れると
定義が長くなるだけで、この科目の到達点の外にあるからである。

なお、**変数を語彙に数えない流儀の本もある**（どの語彙でも共通に使えるものと見て、
述語記号と定数記号だけを語彙と呼ぶ）。続けて本を読むときに食い違って見えても、
中身は同じである。
:::

::: {.term}
$\forall x\, \varphi$ と $\exists x\, \varphi$ の $\varphi$ の部分を、その量化子の**範囲**という。
範囲の中にある $x$ の現れを**束縛された現れ**、そうでない現れを**自由な現れ**という。
自由な現れを1つも持たない論理式を**文**という。
（同じ $x$ が1つの式の中で両方の現れ方をする式も作れるが、このページの例には出てこない。）

- $\mathrm{drinks}(\mathrm{aoi}, \mathrm{cocoa})$ … 原子式で、自由な現れが無いので文
- $\mathrm{drinks}(x, \mathrm{cocoa})$ … 原子式だが $x$ が自由に現れるので文ではない
- $\exists x\, \mathrm{drinks}(x, \mathrm{cocoa})$、$\forall x\, \exists y\, \mathrm{teammate}(x, y)$ … どちらも文
:::

番外(1)の[「開いた文」](logic-intro.md#open-formulas)は、このページの言葉では
**自由な現れを持つ論理式**のことである。このページの「文」には当たらない。
番外(1)は記号を使わないので、日常語の「文」でそう呼んでいた。

**真偽が決まるのは文だけ**である。開いた式は、次の節の付値を添えてはじめて真偽がつく。

## 構造: 論理式に意味を与える舞台 {#structure}

::: {.term}
**構造**とは、語彙のそれぞれに意味を割り当てたものである。$M$ と書く。中身は次の3つである。

- **領域** $D$: 話題にする対象を全部集めた**空でない集合**
- **定数記号の解釈**: 定数記号1つに $D$ の要素を1つ対応させる
- **述語記号の解釈**: $n$ 引数の述語記号 $P$ に、$D$ の要素の $n$ 個組の集合を対応させる。
  これを $P^{M}$ と書き、**関係**という

構造は「どんな世界の話をしているか」を書き下したものである。
:::

### 具体例1: 第01回の知識ベース {#structure-kb}

[第01回](../sessions/01-prolog-intro.md)で書いた `drinks/2` と `club/2` の事実の並びは、
**書いていない組は関係に入れない、という約束のもとで**そのまま構造である
（この約束は Prolog の側のもので、充足関係の定義から出るものではない。
→[Prolog はどこにいるか](#prolog)の warning）。
`drinks(aoi, cocoa).` のような事実は、関係に組を1つ入れる指示になっている。
これを構造 $M_1$ として書き直す。定数記号は、どれも同じ綴りの $D$ の要素を指すものとする。

- $D = \{\mathrm{aoi}, \mathrm{hikaru}, \mathrm{tsubasa}, \mathrm{kaede},
  \mathrm{cocoa}, \mathrm{coffee}, \mathrm{tea}, \mathrm{photo}, \mathrm{tennis}, \mathrm{brass\_band}\}$
- $\mathrm{drinks}^{M_1} = \{(\mathrm{aoi}, \mathrm{cocoa}), (\mathrm{hikaru}, \mathrm{coffee}),
  (\mathrm{tsubasa}, \mathrm{tea}), (\mathrm{kaede}, \mathrm{cocoa})\}$
- $\mathrm{club}^{M_1} = \{(\mathrm{aoi}, \mathrm{photo}), (\mathrm{hikaru}, \mathrm{tennis}),
  (\mathrm{tsubasa}, \mathrm{brass\_band}), (\mathrm{kaede}, \mathrm{photo})\}$

::: important
$D$ に**人も飲み物もサークルも一緒に入っている**ことに注意する。領域は1つしか無く、
種類ごとに分けることはこの定義ではできない（分けて書ける版を**多ソート**というが、扱わない）。
種類を区別したいときは `person(x)` のような述語を足して「$x$ は人である」と**式の中で言う**。
この書き方は次の具体例2で使う。
:::

### 具体例2: 番外(1)の勤務表 {#structure-roster}

番外(1)の[「すべて」と「ある」を重ねると順序が効く](logic-intro.md#nested-quantifiers)に
載っている実測の勤務表も、構造である。

```solver
        1日 2日 3日
職員A   夜  休  夜
職員B   休  日  日
職員C   日  夜  休
職員D   日  日  日
```

リーダー資格を持つのは職員Aと職員Cである（第08回の `small.dzn` のとおり）。これを構造 $M_2$ に
する。定数記号は職員に $\mathrm{A}, \mathrm{B}, \mathrm{C}, \mathrm{D}$、日に $d_1, d_2, d_3$ を使う。
$M_1$ と同じく、定数記号は同じ綴りの $D$ の要素を指すものとする。
職員の名前は大文字だが**変数ではない**（このページで変数に使う文字は $x$ と $y$ だけである）。

- $D = \{\mathrm{A}, \mathrm{B}, \mathrm{C}, \mathrm{D}, d_1, d_2, d_3\}$（職員と日を1つの集合に混ぜる）
- $\mathrm{staff}^{M_2} = \{\mathrm{A}, \mathrm{B}, \mathrm{C}, \mathrm{D}\}$、$\mathrm{day}^{M_2} = \{d_1, d_2, d_3\}$、$\mathrm{leader}^{M_2} = \{\mathrm{A}, \mathrm{C}\}$
- $\mathrm{night}^{M_2} = \{(\mathrm{A}, d_1), (\mathrm{C}, d_2), (\mathrm{A}, d_3)\}$

$\mathrm{night}^{M_2}$ は、上の表で「夜」と書いてあるマスだけを組にして並べたものである
（「休」と「日」のマスは入っていない）。1引数の述語は組が1つ組になるので、
括弧を省いて要素だけを並べてある。
$\mathrm{staff}^{M_2}$ はこのあとの式には現れない（資格者は職員なので $\mathrm{leader}$ だけで足りる）。
構造としてどの述語記号に意味を与えたかを示すために挙げてある。

## 付値と充足: 式がいつ真になるか {#satisfaction}

構造だけでは、自由な現れを持つ式の真偽はまだ決まらない。もう1つ要る。

::: {.term}
**付値**とは、変数それぞれに $D$ の要素を1つ対応させたものである。$s$ と書き、
$s(x)$ で「$s$ が変数 $x$ に対応させた要素」を表す。

**項の値**は、関数記号を扱わないので2通りしかない。
項が定数記号ならその定数記号の解釈、項が変数 $x$ なら $s(x)$ である。
:::

### 充足関係の定義 {#definition}

$M, s \models \varphi$ と書いて「構造 $M$ と付値 $s$ のもとで $\varphi$ が成り立つ」と読む。
$\models$ は「充足する」と読む。定義は式の形ごとに次のように与える。

| 式の形 | $M, s \models$ となるのは | 日本語で言うと |
|---|---|---|
| $P(t_1, \dots, t_n)$ | 項の値の組が $P^{M}$ の要素であるとき | 「その組で関係が成り立っている」と書いてあるとき |
| $\neg \varphi$ | $M, s \models \varphi$ でないとき | $\varphi$ が成り立たないとき |
| $\varphi \land \psi$ / $\varphi \lor \psi$ / $\varphi \to \psi$ | 順に、両方が成り立つとき / 少なくとも一方が成り立つとき / $\varphi$ が成り立たないか $\psi$ が成り立つとき | 命題論理の $\land$ $\lor$ $\to$ と同じ |
| $\forall x\, \varphi$ | $D$ の**どの要素 $e$ を取っても**、$x$ の行き先だけを $e$ に取り替えた付値で $\varphi$ が成り立つとき | $x$ に何を入れても $\varphi$ が成り立つ |
| $\exists x\, \varphi$ | $D$ の**ある要素 $e$ について**、$x$ の行き先だけを $e$ に取り替えた付値で $\varphi$ が成り立つとき | $x$ に入れると $\varphi$ が成り立つものが1つはある |

$\neg$ と $\land$ $\lor$ $\to$ の行は第05回の真理値表をそのまま書き写したもので、
**述語論理で新しいのは、いちばん上の行といちばん下の2行だけ**である。
$\forall$ と $\exists$ の行では「$x$ の行き先**だけ**を取り替える」ことに注意する。
$x$ 以外の変数の行き先は $s$ のまま動かさない。順序が意味を変えるのはここである。

文には自由な現れが無いので、$s$ が何であっても真偽は変わらない
（このことは充足関係の定義から、式の長さについての帰納法で証明できる。
ここでは認めて先へ進む）。そこで文 $\varphi$ については
$s$ を落として $M \models \varphi$ と書き、**$M$ は $\varphi$ の[モデル](#models)である**という。

構造 $M_1$（第01回の知識ベース）で定義を使ってみる。

- $M_1, s \models \mathrm{drinks}(\mathrm{aoi}, \mathrm{cocoa})$ は**真**。組が $\mathrm{drinks}^{M_1}$ にあり、$s$ には依らない
- $\mathrm{drinks}(x, \mathrm{cocoa})$ は $s(x) = \mathrm{aoi}$ なら真、$s(x) = \mathrm{hikaru}$ なら偽。付値しだいで変わる
- $M_1 \models \exists x\, \mathrm{drinks}(x, \mathrm{cocoa})$ は**真**。$x$ の行き先を $\mathrm{aoi}$ にすればよい
- $M_1 \models \forall x\, \mathrm{drinks}(x, \mathrm{cocoa})$ は**偽**。$\mathrm{hikaru}$ で成り立たないし、
  $D$ には飲み物やサークルも入っているので $\mathrm{tea}$ を入れても成り立たない

### 定義どおりに評価してみる {#order}

構造 $M_2$（勤務表）で、番外(1)の読み方Aと読み方Bを式にして評価する。
$D$ には職員も日も混ざっているので、「すべての日について」は $\forall x$ だけでは書けない。
**$\mathrm{day}(x) \to$ で覆って「日でないものには何も要求しない」**とする。

$$\text{読み方A}: \quad \forall x\, \bigl(\mathrm{day}(x) \to \exists y\, (\mathrm{leader}(y) \land \mathrm{night}(y, x))\bigr)$$

$$\text{読み方B}: \quad \exists y\, \bigl(\mathrm{leader}(y) \land \forall x\, (\mathrm{day}(x) \to \mathrm{night}(y, x))\bigr)$$

::: warning
$\forall$ の側は $\to$ で、$\exists$ の側は $\land$ でつないでいる。
「すべての日について〜」は日でない対象に何も要求しないので $\to$、
「ある資格者がいて〜」はその対象が資格者であることも要求するので $\land$ である。
MiniZinc の `forall(d in DAYS)` と `exists(s in STAFF where leader[s])` の範囲指定が、
式の側ではこの形で現れている。
:::

**読み方A**を定義どおりに評価する。$\forall x$ なので $D$ の要素を1つずつ入れるが、
$\mathrm{day}(x)$ が成り立たない要素（職員）では $\to$ が自動的に成り立つ。

| $x$ の行き先 | $\mathrm{day}(x)$ | $\exists y\,(\mathrm{leader}(y) \land \mathrm{night}(y, x))$ | $\to$ 全体 |
|---|---|---|---|
| $\mathrm{A}$ / $\mathrm{B}$ / $\mathrm{C}$ / $\mathrm{D}$ | 偽 | 見なくてよい | **真** |
| $d_1$ | 真 | $y = \mathrm{A}$ で真（$(\mathrm{A}, d_1) \in \mathrm{night}^{M_2}$、$\mathrm{A} \in \mathrm{leader}^{M_2}$） | **真** |
| $d_2$ | 真 | $y = \mathrm{C}$ で真（$(\mathrm{C}, d_2) \in \mathrm{night}^{M_2}$、$\mathrm{C} \in \mathrm{leader}^{M_2}$） | **真** |
| $d_3$ | 真 | $y = \mathrm{A}$ で真（$(\mathrm{A}, d_3) \in \mathrm{night}^{M_2}$） | **真** |

どの行も真なので、$M_2 \models \text{読み方A}$ である。**読み方Aは真**である。

**読み方B**では $\exists y$ が外側なので、先に $y$ を1つ決める。$\mathrm{leader}(y)$ が
真になるのは $y = \mathrm{A}$ と $y = \mathrm{C}$ だけなので、この2つを調べれば足りる。

| $y$ の行き先 | 内側の $\forall x\,(\mathrm{day}(x) \to \mathrm{night}(y, x))$ | 全体 |
|---|---|---|
| $\mathrm{A}$ | $x = d_2$ で偽（$(\mathrm{A}, d_2) \notin \mathrm{night}^{M_2}$） | **偽** |
| $\mathrm{C}$ | $x = d_1$ で偽（$(\mathrm{C}, d_1) \notin \mathrm{night}^{M_2}$） | **偽** |

どちらも駄目なので $M_2 \models \text{読み方B}$ ではない。**読み方Bは偽**である。

$M_2$ は読み方Aが真で読み方Bが偽なので、番外(1)の
[「B が成り立てば A も成り立つが、逆は成り立たない」](logic-intro.md#nested-quantifiers)の
**「逆は成り立たない」の実例**になっている。もう片方の「B が成り立てば A も成り立つ」は
どの構造でもそうだ、という論理的帰結の話なので、このページでは扱わない。

::: important
番外(1)は「$\exists$ の選び方を日ごとに変えてよいかどうかが違う」と言葉で書いた。
その違いは、いま見た**評価の順番**そのものである。

- 読み方A: $\forall x$ が外なので、$x$ を固定した状態で $\exists y$ を探す。
  だから**見つける $y$ が $x$ ごとに違ってよい**（$d_1$ では $\mathrm{A}$、$d_2$ では $\mathrm{C}$）
- 読み方B: $\exists y$ が外なので、$y$ を決めてから $\forall x$ に入る。
  **$y$ を決めた時点で $x$ の情報は使えない**

「依存してよいか」は気分の問題ではなく、**定義を外側の量化子から順に当てること**と、
そのとき**$x$ 以外の変数の行き先は動かさないこと**の2つから出てくる帰結である。
:::

## モデル、充足可能、充足不能 {#models}

::: {.term}
- 文 $\varphi$ について $M \models \varphi$ が成り立つとき、$M$ を $\varphi$ の**モデル**という
- 文 $\varphi$ が**充足可能**とは、$\varphi$ のモデルが**少なくとも1つある**ことである
- 文 $\varphi$ が**充足不能**とは、$\varphi$ のモデルが**1つも無い**ことである
- 文の集合 $\Gamma$ については、$\Gamma$ の**すべての**文のモデルになっている $M$ を $\Gamma$ のモデルという
:::

制約は「同時に満たしたい条件」の集まりなので、文の集合のほうが本番である。
$\Gamma$ に文を足すとモデルは減りこそすれ増えない。条件を足すと解が減るのと同じ話である。
[第05回](../sessions/05-sat-dependencies.md)の $p \land \neg p$ が UNSAT だったのと同じ立場で、
**充足不能は「モデルが1つも無いことが確かめられた」という結果**であって、
書き方が壊れているという意味ではない。
命題論理では、これがそのままソルバーの UNSAT である。
述語論理でソルバーにつなぐときは注意が1つ要るので、
[CSP の語彙との対応](#csp-correspondence)で足す。

::: note
このあとには**妥当**（どの構造でも真）、**論理的帰結**（前提のモデルが必ず結論のモデルになる）、
それを紙の上の書き換えだけで示す**証明**という話題が続く。
**このページでは扱わない。**名前だけ挙げておく（→[扱わないこと](#not-covered)）。
:::

## 本科目の道具は何をしているか {#solvers}

### 有限領域なら量化子は展開できる {#finite-expansion}

領域 $D$ が有限で、要素が $e_1, \dots, e_n$ と数え上げてあり、さらに**どの要素にも名前
（定数記号）がある**とする。このとき $\forall$ と $\exists$ の定義の行から次が出る
（$\equiv$ の左右は、$M$ と**任意の付値 $s$** のもとで同じ真偽になる、という意味である。
$\varphi$ に $x$ 以外の変数が自由に現れていてもよいので、付値まで言っておく必要がある）。

$$\forall x\, \varphi \;\equiv\; \varphi[x := e_1] \land \dots \land \varphi[x := e_n]$$

$$\exists x\, \varphi \;\equiv\; \varphi[x := e_1] \lor \dots \lor \varphi[x := e_n]$$

$\varphi[x := e]$ は「$x$ のところに $e$ の名前を書き入れた式」である。$\forall$ は
「どの要素でも成り立つ」だったから**有限個の $\land$**、$\exists$ は「成り立つ要素が1つはある」
だったから**有限個の $\lor$** になる。定義から出てくるだけで、新しい約束は足していない。

- **MiniZinc**: `forall(r in ROWS)( … )` と `exists(…)( … )` がまさにこの展開である。
  範囲をその場に書かせるのは、展開先を確定させるためである。
  [読み方A](#order)を $D$ の7要素で展開すると7項の $\land$ になるが、そのうち職員の4項は
  $\mathrm{day}(x)$ が偽なので $\to$ が自動的に真になる。
  `forall(d in DAYS)` は、その4項を最初から省いて日の3項だけを並べた形である
- **Z3Py**: Python の `for` で `s.add(...)` を並べ、`And(...)` / `Or(...)` に詰めるのが同じことである。
  第05回で `s.assertions()` に展開後の式が並んで見えたのは、この姿である

::: warning
**$D$ が無限だとこの書き換えはできない。**「すべての整数について」を $\land$ で並べ切れないからである。
この科目の題材は領域が有限で要素を数え上げてあるので、いつでも展開できる。番外(1)で
「Z3 の `ForAll` は名前だけ知っておけばよい」と書いたのは、これが理由である。
:::

### CSP の語彙との対応 {#csp-correspondence}

[第03回](../sessions/03-minizinc-sudoku.md)の「変数・定義域・制約・割当て・解」を置き換える。

| CSP の語彙 | 意味論の言葉 |
|---|---|
| 決定変数への割当て | 構造の**まだ決まっていない部分**（このページの勤務表なら $\mathrm{night}^{M}$）を1つ定めること |
| 定義域 | 決め方の候補の範囲 |
| 制約 | 文（自由な現れの無い論理式） |
| 解 | 制約すべてのモデルのうち、**入力で固定した部分を保っているもの** |
| ソルバー | モデルを探す機械 |
| UNSAT | **入力で固定した部分を保ったままでは**モデルが1つも無いと分かった状態 |

決定変数と関係が1対1に対応するとは限らない。第08回の `roster[s, d]` は
`day`・`night`・`off` の3値を取るので、日勤・休みまで見るなら関係を3つ用意し、
「どのマスもちょうど1つ」の文を足すことになる。
このページでは夜勤の関係 $\mathrm{night}^{M}$ だけを見ている。

::: important
要点は、構造に**分かっている部分と決めてほしい部分がある**ことである。勤務表なら
$\mathrm{day}^{M}$ と $\mathrm{leader}^{M}$ が入力、$\mathrm{night}^{M}$ が決めてほしい部分にあたる。
ソルバーはそこの入れ方を変えながら、制約の文がすべて真になる構造を探している。

**注意**: [モデル、充足可能、充足不能](#models)の「充足可能」は、構造を何も固定しない問いである。
どんな領域でも、どんな入力でもよいから、モデルが1つでもあるか、と聞いている。
ソルバーの SAT / UNSAT は、領域と入力を固定したうえでの、**それより狭い問い**に答えている。
だから「UNSAT」は「その文の集合が充足不能」と同じ意味ではない。
番外(1)の[読み方B](logic-intro.md#nested-quantifiers)が `=====UNSATISFIABLE=====` になっても、
読み方B・休息制約・必要人数を文にした集合そのものは充足可能である。
日が1つしかない構造や、職員がもっと多い構造を選べばモデルはある。
このページは等号を扱わないので、「領域の要素はこの7つだけ」を文の側に書くこともできない。
:::

### Prolog はどこにいるか {#prolog}

- **事実**の並び（`drinks(aoi, cocoa).` など）は、関係を列挙して構造を書き下したものである
  （下の warning の約束、つまり**書いていない組は関係に入れない**、のもとで構造が1つに決まる）
- **規則** `teammate(X, Y) :- club(X, C), club(Y, C).` は、変数を $\forall$ で閉じた含意
  $\forall x\, \forall y\, \forall c\,(\mathrm{club}(x, c) \land \mathrm{club}(y, c) \to \mathrm{teammate}(x, y))$ である。
  本によっては、頭に現れない $c$ を本体側の $\exists$ で書く（$\exists c\,(\dots)$）。同じ意味である
- $M_1$ には $\mathrm{teammate}^{M_1}$ が無い（語彙にも `teammate` が無い）ので、
  この規則の文は $M_1$ では**まだ評価できない**。
  Prolog は、事実で決めた部分を保ちつつ、**この文が真になるように $\mathrm{teammate}^{M}$ を
  必要最小限だけ入れた構造**を使って答える（これを最小モデルというが、扱わない。
  →[扱わないこと](#not-covered)）
- **クエリ** `drinks(X, cocoa)` は $\exists x\, \mathrm{drinks}(x, \mathrm{cocoa})$ を問うことである。
  返る `X = aoi.` は、$\exists$ の行がいう「ある要素 $e$」を実際に指して見せたものである

::: warning
第01回の「**書いていないことは偽として扱われる**」は、充足関係の定義から出てくる話では**ない**。
定義のほうは「$P^{M}$ に入っていれば真」としか言っておらず、$P^{M}$ の中身は構造しだいである。
「書いていないものは $P^{M}$ に入れない」というのは Prolog の側の約束であって、
これを**閉世界仮説**という。名前だけ挙げておく（→[扱わないこと](#not-covered)）。
:::

## 扱わないこと {#not-covered}

- **関数記号と一般の項、等号** → 扱わない。項は定数記号か変数だけとし、`x = y` も書けないものとした
  （[何が論理式か](#syntax)）
- **多ソート（種類ごとに領域を分ける書き方）** → 扱わない。種類の区別は `day(x)` のような述語で式の中に書く
- **無限の領域** → 扱わない。この科目の題材はすべて有限である
- **妥当・論理的帰結・証明（健全性・完全性）**、**Prolog の閉世界仮説と最小モデル**、
  **否定と量化子の関係**（$\neg \forall$ と $\exists \neg$ の言い換え） → 扱わない。名前だけ挙げた

::: important
このページの用語（構造・領域・解釈・付値・充足・モデル・原子式・文 など）は
**このページの中だけで完結する**。[用語集](glossary.md)には載せていない。
用語集にあるのは第01〜10回で導入する用語だけだからで、番外(1)と同じ扱いである。
:::
