条件を満たす割当が複数あるとき、評価値を使ってその中から選ぶ。講座の合計不満度を小さくする問題から始め、二種類のキットを何個作るかを決める問題へ進む。守る条件と、良くしたい量を分けて考えよう。

目標

この回では、実行可能な解を見つけるところから、目的値で比較するところへ進む。結果を表示できたら、次の三つを説明できるようになろう。

  • 実行可能性・目的値・最適性を区別できる。
  • 入力の係数と決定変数から合計を作り、最小化・最大化を選べる。
  • 製作個数の意味と、容量から導いた安全な定義域を説明できる。

第05回の0/1表、許可と定員、添字付きの和を使う。完成した4人の基本割当と入力を再配布するので、前の必修の完成は不要である。個数の整数変数と最適化は、この回で説明する。操作は最適化の確認手引きを使って授業内で確認できる。

説明・実演に50分、5. 演習に45分、振り返りに5分を使う。必修1は15分、必修2は25分、残り5分は確認の目安である。通常演習の提出・宿題・完了報告はなく、教員の完了承認も待たない。発展は選んで取り組む。

1. 問題

同じ許可と定員を守る割当でも、参加先への満足度は異なる。ここでは小さいほど望ましい「不満度」を数で与える。許されるかどうかと、許された中でどれがよいかを分けて読む。

条件と入力 4人A〜Dを講座1〜3へ一人ちょうど一つ割り当てる。許可が1の組合せだけを選び、各講座の人数は定員以下とする。空席を残してもよい。

人 講座1の許可 講座2の許可 講座3の許可
A 1 1 0
B 1 0 1
C 1 1 1
D 0 1 1
定員 2 1 1

不満度は次の表とする。実際に選んだ各人の参加先の不満度を足し、その合計が最も小さい割当を求める。

人 講座1の不満度 講座2の不満度 講座3の不満度
A 0 1 0
B 2 1 3
C 1 4 0
D 3 3 2

禁止位置にも不満度の欄はあるが、その値が小さいから選んでよいわけではない。Aの講座3の不満度は0でも、許可が0なので選べない。許可と定員の条件は、評価値を加えた後も必要である。

2. 定式化

まず元の問題の条件を保ち、条件を満たす割当の中で比べる量を定義する。この順序を意識すると、目的を変えたときにも、守るべき条件が消えていないかを確かめられる。

実行可能な割当

x_{p,c}\in\{0,1\}を、人pが講座cを選ぶかどうかとする。許可の入力をa_{p,c}、定員を\mathrm{cap}_cとすると、引き継ぐ条件は次の三種類である。

\sum_c x_{p,c}=1\quad(各人p),\qquad \sum_p x_{p,c}\le\mathrm{cap}_c\quad(各講座c),\qquad x_{p,c}\le a_{p,c}\quad(各組p,c).

これらをすべて満たす解を実行可能解と呼ぶ。第05回ではそのうち一つを求めた。今回は、実行可能解の集合を保ったまま、その中に比較の基準を加える。

合計不満度

入力の不満度を\mathrm{cost}_{p,c}とし、合計をTと置く。選ばない位置はx_{p,c}=0なので寄与が0、選んだ位置は1なのでその不満度が一度だけ加わる。

T=\sum_{p,c}\mathrm{cost}_{p,c}x_{p,c}.

このように、解の良さを数で表し、比較に使う式を目的関数と呼ぶ。ある解におけるTの値が目的値であり、実行可能解全体の中で最も小さい値が最適値である。その値を達成する解を最適解と呼ぶ。

合計の最小化は、すべての人の不満度を同時に最小にすることとは異なる。誰かの不満度が上がっても、全体の合計が下がる選び方はあり得る。今回の比較基準は、問題で指定された合計Tである。

個数と安全な境界

別の題材として、製品の個数qを考える。一つ作ると材料2を使い、材料の容量が8なら、非負の整数qに対して 2q\le8 が必要であり、0\le q\le4 と分かる。

qは「作るかどうか」ではなく「何個作るか」を表す。0/1へ狭めると、2個以上作れる正しい解を失ってしまう。一方、容量から導いた上限4は、元の条件を満たす解を失わない安全な境界である。

使用量が容量以下という制約と、その条件から導いた変数の範囲は区別して読む。複数の資源を使う場合は、それぞれの容量を守る必要がある。必修2で、二種類の個数と二つの資源を組み合わせる。

3. 解説例

教員が、完成した基本割当から合計と最小化を加えて実演する。ファイルの手順1〜3を読み、最後に個数変数の短い例を試す。実行中に解が出ることと、最適終了することを分けて確認しよう。

手順1　基本条件の再開

cost-demo.mznは、assignment-core.mznから変数と、一人一講座・許可・定員の三条件を読み込む。基本モデルからsolveと表示だけを分けたファイルである。

新しく加えたcostも人×講座の入力で、varは付けない。cost-base.dznに許可・定員・不満度をまとめてある。5人版や、AとDを分ける条件は含めない。

手順2　合計不満度

すべての人と講座の組について、入力の不満度と選択変数を掛けて足す。数式のTへ、MiniZincではtotalという名前を付ける。各セルの値を更新する手続きではなく、値の関係を定義している。

例えばAが講座2を選ぶと、Aの行からは0\times0+1\times1+0\times0=1が加わる。同じ計算を各人について行い、選んだ四つの不満度の合計を作る。totalは割当に応じて決まる値なのでvarが付く。

手順3　最小化と終了状態

solve satisfy;の代わりに、比較したい量を付けて最小化を指定する。一つのモデルにsolveを二つ書くのではなく、今回求める問題の種類を一つ指定する。

Gecodeで実行する。出力には割当表とtotalが表示される。合計値だけを見ず、参加先を読み取って元の三条件と不満度を照合しよう。

minizinc --solver gecode cost-demo.mzn cost-base.dzn

解の区切り----------は一つの解が出たことを表す。最適化では、最後の==========が最適性まで確認した終了を示す。実行中や時間制限で停止した場合、表示された候補よりよい解が残っている可能性がある。詳しい操作は確認手引きで確認できる。

手順4　個数と最大化

quantity-demo.mznでは、先ほど導いた範囲で材料の容量を守り、製作個数qを最大にする。値の範囲が0/1から0〜4へ変わる理由と、目的を大きくする理由を別々に説明しよう。

この問題の最適解はq=4である。maximizeは目的値を大きくする指定であり、配列内の最大の要素を取り出す演算ではない。何を良くするかによって、最小化と最大化を選ぶ。

4. 結果

4人の基本割当には四つの実行可能解がある。それぞれについて選んだ不満度を足すと、どの解が今回の目的にとってよいかを比較できる。参加先はA・B・C・Dの順に並べる。

参加先 各人の不満度 合計T
1, 1, 2, 3 0, 2, 4, 2 8
1, 1, 3, 2 0, 2, 0, 3 5
1, 3, 1, 2 0, 3, 1, 3 7
2, 1, 1, 3 1, 2, 1, 2 6

最適値は5で、参加先1・1・3・2が達成する。合計8の割当も条件を満たしているが、今回の目的では最適ではない。「条件違反」と「もっとよい解がある」を区別しよう。

この小さな例では、四つすべてを並べることでも最適性を確かめられる。一般には、見つけた一解の目的値を手で計算しただけでは最適性の証明にはならない。実行可能性の確認、目的値の再計算、最適終了の確認を順に行う。演習では、入力や題材を変えて同じ区別を使う。

5. 演習

必修1は同じ割当で不満度を変更し、必修2は生産量という別の題材へ移る。どちらも出力の値を元の条件と照合する。目的値がよさそうに見えても、容量や許可を落としていないか確認しよう。

必修1　不満度の変更

許可と定員を保ち、一つの不満度だけを変える。目的値が変わることと、実行可能な割当が変わることを区別する練習である。出発モデルには基本条件が揃っている。

問題

条件と入力 4人A〜Dを講座1〜3へ一人ちょうど一つ割り当てる。許可が1の組合せだけを選び、各講座の人数は定員以下とする。空席は許す。

人 講座1の許可 講座2の許可 講座3の許可
A 1 1 0
B 1 0 1
C 1 1 1
D 0 1 1
定員 2 1 1

次の不満度で、選んだ参加先の合計を最小にする。

人 講座1の不満度 講座2の不満度 講座3の不満度
A 0 1 0
B 2 1 3
C 1 4 4
D 3 3 2

解説例から変えたのはCの講座3の不満度だけで、0から4にした。人の番号はA=1〜D=4とする。

作業

cost-start.mznとassignment-core.mznを同じフォルダーへ置く。後者には一人一講座・許可・定員の条件が入っている。x[p,c] は人pが講座cを選ぶなら1、選ばないなら0、cost[p,c] はその参加先の不満度を表す。PEOPLE は人の番号1〜4、COURSES は講座番号1〜3である。入力宣言と表示は用意してあるが、表示で使うtotalの定義とsolveはまだない。

  1. 作業1： 不満度と0/1変数を掛けた合計をtotalとして定義する。
  2. 作業2： 合計の最小化を指定し、cost-practice.dznで実行する。選んだ四つの不満度を別に足し、表示と終了状態を確かめる。

自己確認

最適値は6で、参加先2・1・1・3が達成する。個人の不満度は1・2・1・2である。比較用の割当1・1・3・2は、この問題の不満度では合計9になり、許可と定員には引き続き違反しない。

続いて評価入力をcost-zero.dznへ交換し、同じモデルで実行する。すべての不満度が0のとき、どの割当が最適になるかを先に予想しよう。最適値は0で、この問題の許可・定員・一人一講座を満たす四つの割当はすべて同点になる。新しい割当が許されたのか、比較の結果が変わったのかを説明する。

出力の表が条件を満たすこと、合計が表示と一致すること、最適終了していることを別々に確認する。Gecodeの出力末尾の ========== は最適終了を表す。途中の候補が出ただけ、または時間切れの場合は最適とは判断しない。許可・定員・一人一講座を満たす割当の範囲は変わらず、評価入力を変えたことだけを理由に割当を禁止しない。

ヒントを開く：選んだ四つだけを足す

出力の各行で1がある講座を選び、不満度表の同じ位置を一つずつ拾う。costの全欄を足すのではない。コードでもcost[p,c]*x[p,c]によって、選んでいない位置の寄与を0にする。

必修2　二種類のキットの生産量

今度は参加先の選択ではなく、二種類の製作個数を決める。資源ごとの使用量と、得点の合計を分けて表そう。割当の一人一講座という条件を、この問題へ持ち込まないようにする。

問題

条件と入力 二種類のキットを、それぞれ0個以上の整数個だけ作る。端数と負の個数は不可。材料容量と作業時間の容量はいずれも8で、どちらも超えてはいけない。使い切る義務はない。

キット 1個の材料消費 1個の時間消費 1個の得点
1 2 1 3
2 1 2 4

求めるのは、資源容量を守り、得点合計を最大にする二つの製作個数。どちらか一種類だけを作っても、両方を作ってもよい。

作業

kits-start.mznには入力の宣言と使用量の表示を用意した。material_capacity は材料容量、time_capacity は時間容量、score_u・score_v はキット1・2の1個当たりの得点で、この問題では順に8・8・3・4である。出力で使うu・vを二つの個数として宣言し、どちらがどのキットかをコメントにも書こう。

  1. 作業1： キット1の個数をu、キット2の個数をvとする。非負性と容量から各上限を導き、整数変数を宣言する。材料と時間それぞれの使用量を計算し、容量以下の制約を書く。
  2. 作業2： 得点合計scoreを定義し、最大化を指定する。kits.dznで実行し、個数・材料・時間・得点を再計算する。

自己確認

最適解はu=2、v=3で、材料7、時間8、得点18になる。材料を使い切っていなくても正しい。u=3、v=3は両資源を9使うので拒否する。u=v=0は実行可能だが、得点0なので元の問題では最適ではない。

容量を等号にしたり、根拠なく個数を0/1にしたりすると、別の問題になってしまう。固定して検査する方法で条件の過不足を調べられる。固定した問題で最適と出ても、元の自由に個数を選ぶ問題で最適とは限らない。

ヒントを開く：資源ごとの足し算

材料はキット1が1個で2、キット2が1個で1を使うので、使用量は2*u+v。時間も同じように、その資源の係数と個数を掛けて足す。得点は資源使用量と別の係数を使う。

ヒントを開く：片方だけ作る場合

もう一方の製作個数を0にしたとき、材料と時間それぞれから何個まで作れるかを調べる。もう一方を増やしてもその上限を超えられない理由を、資源を消費する向きと非負性から説明しよう。

ヒントを開く：確認例・安全な上限

vが非負なら、材料の条件から2*u <= 8なのでu≤4。uが非負なら、時間の条件から2*v <= 8なのでv≤4。var 0..4という宣言なら、これらの条件を満たす個数を失わない。上限だけで二つの容量制約を省略はできない。

6. 発展

一つの最適解から先には、すべての最適解を求める、上限の証明を作る、目的に優先順位を付けるという方向がある。独立した発展ページで、必要な出発点から選んで始められる。

選択 深めること
発展1　すべての最適な割当 最適値を固定し、すべての最適な割当を列挙する
発展2　上限による最適性の説明 容量の不等式から得点の上限を導き、最適性を説明する
発展3　目的に優先順位を付ける 得点を優先し、その中で時間を減らす二段階法と重み
選択M06a　各一つだけの持ち物 各一つだけの品物を選ぶ0/1ナップサック
選択M06b　二種類のケーキ 五つの材料からケーキの製作個数を決める

第07回では勤務表をまず充足問題として作り、第08回で希望などの指標を最適化する。今回の発展の全列挙・優先順位の実装は、次の通常回の前提にしない。

7. 振り返り

自分のモデルについて、何を決め、何を必ず守り、何を良くするかを順に説明しよう。そのうえで、得られた解の目的値を計算したことと、最適性を確認したことの違いを振り返る。

  • 不満度が小さくても、許可されていない参加先を選べないのはなぜか。
  • キットの変数を0/1にせず、0〜4の整数にした根拠は何か。
  • 最適化の実行が途中で止まった場合、表示された解について何が言えるか。

参照

最適化では、解と目的値だけでなく終了状態も確認する。複数の正解がある場合や、目的値が同じ解がある場合も、問題の条件を満たしていれば正しく扱おう。

用語・記法 意味・参照先
実行可能解 すべての制約を満たす解
目的値／最適値 一解の評価値／実行可能解全体で最もよい値
solve minimize total; totalを最小にする
solve maximize score; scoreを最大にする
安全な境界 元の条件を満たす解を失わない変数の範囲
配布と確認 モデル・入力・終了状態の確認手引き
記法の原典 MiniZinc公式教材：算術と最適化

solveの二重指定、許可制約を削除する誤り、容量を等号にする誤りに注意する。結果へ戻り、元の実行可能な解の集合と、比較している目的を確かめよう。
